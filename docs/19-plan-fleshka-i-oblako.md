# План: агент на флешке и подключение облачной модели

Черновик 13.10.2026. Только план — ничего из этого ещё не сделано. Цифры размеров
сняты с рабочей станции разработчика (RTX 4060 Ti 8 ГБ).

## Из чего состоит агент сейчас

| Часть | Где | Размер |
|---|---|---|
| Python с библиотеками (`.venv`; в установщике — встраиваемый Python) | `python\` | ~180 МБ |
| Код агента и база знаний (без медиа уроков ИИТБ) | `agent\*.py`, `agent\kb`, `agent\academy` | ~20 МБ |
| Медиа уроков ИИТБ (`agent\iitb\work`) — на флешку не нужны, в базу уже переложены | — | 1,2 ГБ |
| Панель в R-Pro: `AiBridge.Core.dll` + загрузчик `Plugin.AiBridge.dll` | `core\`, `loader\` | 0,3 МБ |
| Мост внутри R-Pro (`My Commands\AIAgentBridge`) | папка пользователя | < 1 МБ |
| Ollama (программа с библиотеками CUDA) | — | ~1,5–2 ГБ |
| Модель `qwen3:8b` / `qwen3:4b` / `qwen3:1.7b` | — | 5,2 / 2,6 / 1,4 ГБ |

Сервер агента `serve.py` (порт 8766) ходит к Ollama (11434) и к мосту R-Pro (8765);
модель вызывается в одном месте — `agent/llm_ollama.py` (`chat`, `look`, `warm_up`).

## 1. Компактная версия на флешке

**Цель:** вставить флешку в компьютер с R-Pro, запустить один файл — и работать с
агентом без установки, без прав администратора и без интернета; вынуть — и на
компьютере ничего не осталось.

### Комплекты

| Комплект | Состав | Объём | Для чего |
|---|---|---|---|
| Лёгкий | Python, агент, Ollama, `qwen3:4b` | ~5 ГБ | ноутбуки, слабые видеокарты; команды и навыки кодом работают одинаково, модель — только на свободные просьбы |
| Полный | + `qwen3:8b` и зрение `qwen2.5vl:7b` | ~15 ГБ | как на рабочей станции |
| Без модели | Python, агент, адрес внешней модели (сервер цеха или облако — см. п. 2) | ~0,3 ГБ | компьютеры без видеокарты |

Флешка — USB 3.x от 32 ГБ, файловая система exFAT или NTFS (файлы моделей больше 4 ГБ,
FAT32 не подходит).

### Как устроить

1. **Сборка флешки** — `installer\build_usb.ps1` на основе `build.ps1`: тот же каталог
   `stage` (встраиваемый Python, агент, мост, DLL панели) плюс переносная Ollama и папка
   `models`. Исключить `agent\iitb\work`, `__pycache__`, результаты прогонов.
2. **Запуск** — `Запустить агента.cmd` в корне флешки:
   - `OLLAMA_MODELS=<флешка>\models`, Ollama на свободном порту (например 11435, чтобы не
     столкнуться с установленной), `OLLAMA_URL` для агента — туда же;
   - мост: скопировать `AIAgentBridge` в `Документы\R-Pro\0.2\My Commands` (папка
     пользователя, прав администратора не нужно), `bridge.json` не перезаписывать;
   - панель: путь к `AiBridge.Core.dll` на флешке — в `HKCU` (`CorePath`, как для
     разработческой сборки — см. память «Подключение панели в R-Pro»). Нужен загрузчик
     `Plugin.AiBridge.dll` в папке R-Pro — он ставится один раз установщиком (с правами
     администратора). Где загрузчика нет — **режим без панели**: та же беседа в окне
     браузера (`serve.py` уже отвечает по HTTP; добавить простую страницу чата на
     127.0.0.1) — мост работает и без панели;
   - запустить `serve.py` с логом на флешку и прогреть модель.
3. **Завершение** — `Остановить агента.cmd`: остановить `serve.py` и Ollama, убрать
   `CorePath` из `HKCU`, по желанию удалить мост из `My Commands`.
4. **Проверки при старте** (короткий отчёт в окне): R-Pro запущена и мост отвечает;
   доступен сервер лицензий R-Pro (без него R-Pro не стартует — частая причина «не
   работает»); видеокарта и её память → выбрать 8b или 4b; свободен ли порт.

### Что учесть

- **Скорость.** Первая загрузка модели с флешки — 15–60 с (5 ГБ при 100–400 МБ/с);
  потом модель в памяти видеокарты, флешка не мешает. По желанию — кэш моделей на
  локальном диске с очисткой при «Остановить».
- **Без видеокарты** 4b на процессоре даёт единицы токенов в секунду — для такого
  компьютера нужен комплект «без модели» (сервер цеха или облако).
- **Безопасность.** На флешке инструмент `rpro_exec` (произвольный код в R-Pro): по
  умолчанию оставить включённым, как сейчас, но с `allow_exec` в `bridge.json`;
  флешку для выдачи на сторону — с BitLocker To Go.
- **Обновление.** Флешка проверяет `latest.json` на rpro.itc, если есть сеть, и
  предлагает обновить агент (модели — отдельно, по запросу).

### Шаги и оценка

| Шаг | Оценка |
|---|---|
| `build_usb.ps1`: состав, исключения, переносная Ollama | 0,5 дня |
| Запуск/остановка, проверки при старте, выбор модели по памяти видеокарты | 0,5 дня |
| Страница чата в браузере (режим без панели) | 0,5 дня |
| Проверка на «чистом» компьютере: без интернета, без прав администратора, с загрузчиком и без | 0,5 дня |

## 2. Облачная (внешняя) модель

### Что это даст

- **Качество на свободных просьбах.** 8B без кода выбрала правильный инструмент в 2
  из 17 базовых навыков (прогон 06.10), путала единицы, «очищала сцену» сама. Модели
  уровня Claude/GPT/крупных Qwen надёжно выбирают инструмент, планируют многошаговую
  работу (построить → прогнать → найти узкое место → поправить) и пишут код Python 2.7
  для `rpro_exec` с первого раза. Меньше придётся закреплять кодом в `intents.py`.
- **Длинный контекст.** 8 тыс. токенов сейчас против 128–200 тыс.: страницы справки,
  состав сцены на 400 компонентов и вся беседа помещаются целиком, не надо резать.
- **Зрение лучше** — снимки окна R-Pro, чертежи и планировки (DWG ПП-1 из `plans/`)
  читаются точнее, чем `qwen2.5vl:7b`.
- **Компьютер без видеокарты** — агент работает на любом ноутбуке; флешка «без
  модели» весит 0,3 ГБ.
- **Скорость** сложных ответов: облако отвечает за секунды там, где 8B думает минуты.

### Цена и риски

- **Данные уходят за периметр.** В требованиях проекта (`docs/02-arhitektura.md`)
  записано: «только локальный контур, данные проектов не покидают сеть предприятия».
  Наружу ушли бы фразы пользователя, имена и свойства компонентов, результаты
  инструментов, снимки экрана. Нужно решение службы безопасности; без него — только
  «частное облако» (сервер с GPU внутри сети) — переключение уже есть (`OLLAMA_URL`,
  `docs/04-lokalnye-modeli.md`).
- **Доступность и оплата.** Зарубежные API (Anthropic, OpenAI) из России — вопрос
  доступа и оплаты; российские (YandexGPT в Yandex Cloud, GigaChat, Cloud.ru) — договор
  и 152-ФЗ проще, качество вызова инструментов надо мерить.
- **Сеть.** Сервер itc19 без интернета; рабочим станциям нужен выход (прокси).
- **Деньги.** Один ход с инструментами — 10–30 тыс. токенов на входе (описания
  инструментов + история); прогон модуля A — несколько ходов. Порядок — рубли–десятки
  рублей за сложную просьбу; команды и навыки кодом остаются бесплатными.

### Как подключить

1. **Слой модели `agent/llm.py`** вместо прямых вызовов `llm_ollama`: `chat(messages,
   tools)`, `look(image, question)`; поставщики — `ollama` (как сейчас, без изменений
   поведения), `openai` (любой OpenAI-совместимый адрес: vLLM на своём сервере,
   OpenRouter, YandexGPT в режиме совместимости), `anthropic` (Messages API: схемы
   инструментов → `input_schema`, ответы `tool_use` → наш формат).
2. **Настройки**: `RPRO_LLM=ollama|openai|anthropic`, адрес, модель; ключ — в
   диспетчере учётных данных Windows (DPAPI), не в `bridge.json` и не в логе.
3. **Гибрид (маршрутизация)**: команды и навыки кодом — как сейчас, мгновенно и без
   сети; простые просьбы — локальная модель; сложные (стройка, отчёт с правками,
   диагностика, свободный код) или когда локальная не справилась — облачная; нет сети
   — локальная, с пометкой в ответе.
4. **Защита данных**: облако включается явно (переключатель в панели «Модель: локальная /
   облачная», видно в каждом ответе); перед отправкой — замена путей и имён файлов
   заказчика; снимки экрана — только с отдельного разрешения; журнал «что ушло наружу».
5. **Проверка**: прогнать на обоих поставщиках `agent/eval_routes.py`, стенд базовых
   навыков (17 фраз) и фразы TechSkills (`test_task/field/ask_agent.py`) — сравнить
   точность, время и стоимость; решение — по цифрам.

| Шаг | Оценка |
|---|---|
| `llm.py` + поставщик ollama (поведение прежнее, стенды проходят) | 0,5 дня |
| OpenAI-совместимый и Anthropic поставщики, ключи, настройки | 1 день |
| Гибрид и защита данных (переключатель, фильтр, журнал) | 1 день |
| Сравнительный прогон стендов, отчёт | 0,5 дня |
