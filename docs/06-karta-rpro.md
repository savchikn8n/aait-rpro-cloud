# Карта R-Pro и база знаний агента

Итог полного обхода программы (сентябрь 2026). Цель — чтобы агент знал R-Pro не
хуже опытного пользователя и мог со временем собирать работающую ячейку по
описанию обычными словами.

Документ отвечает на три вопроса: из чего состоит программа, что из этого агент
уже знает и умеет, чего не хватает до «собери текстом».

## Откуда взяты знания

| Источник | Что в нём | Объём |
|----------|-----------|-------|
| `Help\Help_RP_ru.chm` | русская справка: интерфейс, задачи, все операторы, поведения, элементы | 413 разделов |
| `Help\Python_API.chm` | справка по Python-API с примерами | 222 раздела |

Всё это собрано в `agent/kb/` (1102 фрагмента) скриптом `agent/kb_build.py`;
карту ленты снимает `agent/kb_ui_dump.ps1` с запущенной программы. Как
пересобрать — в конце документа.

## Из чего состоит программа

### Главное понятие: компонент

Планировка (сцена) — это набор **компонентов**. Компонент — дерево **узлов**;
узел несёт **элементы** (геометрию), **свойства** и **поведения**. Подвижные
части — узлы-**звенья** с типом соединения и степенями свободы.

Поведение — то, что компонент делает сам. Десять групп по справке:

| Группа | Поведения |
|--------|-----------|
| Интерфейсы | один к одному, один ко многим — физическая стыковка (PnP) |
| Кинематика | шарнирная, декартова, дельта, параллелограмм, SCARA, на Python |
| Материальный поток | генератор компонентов, контейнер, контроллер ёмкости, односторонний и двусторонний путь, прокси потока, правило маршрутизации |
| Модель процесса | генератор деталей, транспортный контроллер, исполнитель процесса, транспортный узел |
| Датчики | точки процесса, луч, объём, путь |
| Сигналы | логический, целый, вещественный, строковый, матричный, компонентный, карта сигналов |
| Робототехника | контроллер робота, исполнитель, сервоконтроллер, контейнеры баз и инструментов |
| Физика | объект, соединение, кабель, траектория |
| Разное | скрипт Python, статистика, примечание, транспортное средство, контейнер действий и др. |

Компоненты связываются двумя способами:

- **интерфейсами** — физически: конвейер к конвейеру, захват к фланцу робота
  (кнопка «PnP» или «Интерфейсы»);
- **сигналами** — логически: датчик к входу робота, выход робота к захвату
  (кнопка «Сигналы»). Для новых связей справка советует входы и выходы робота
  с номера 100: 1–81 заняты предопределёнными действиями.

### Два способа описать работу ячейки

1. **Моделирование процессов («МП» в каталоге)** — вкладка ПРОЦЕСС. Задаются
   типы деталей, шаги процесса и транспортные связи между ними; перевозят
   деталь транспортные контроллеры (робот, человек, конвейер, AGV). Логика
   шага записывается **операторами процесса** — их 43: Создать, Транспорт В,
   Транспорт Из, Работа, Задержка, Буфер, Если, Пока, Ждать сигнал, Отправить
   сигнал, Выполнить процедуру робота, сборка и разборка и др.
2. **Программа робота** — вкладка ПРОГРАММИРОВАНИЕ. **Операторы робота** —
   их 21: движение по точкам, линейное, по траектории, установить выход, ждать
   вход, вызов подпрограммы, задержка, условия и циклы.

Для «собери текстом» основной путь — первый: он описывает поток деталей
словами, близкими к тому, как говорит человек («деталь приходит по конвейеру,
робот ставит её в станок, станок обрабатывает 30 секунд»).

### Вкладки ленты

Полная карта с внутренними id — `agent/kb/ui_ribbon.md`.

| Вкладка | Назначение | Ключевые группы |
|---------|------------|-----------------|
| ГЛАВНАЯ | планировка | Действия (Переместить, PnP, Взаимодействие), Инструменты (Измерение, Привязка, Выровнять, Паттерн), Соединить (Интерфейсы, Сигналы), Иерархия, Импорт/Экспорт, Статистика, Камера |
| ПРОЦЕСС | моделирование процессов | Инструменты транспортных ссылок (Очистить, Автоматические, Установить контроллер), Помощники (система координат, сигнал), Редактор (Детали, Операции, Процесс) |
| МОДЕЛИРОВАНИЕ | устройство компонента | Компонент (Создать, Сохранить), Структура (звенья), Геометрия, Поведение, Свойства, Мастер |
| ПРОГРАММИРОВАНИЕ | роботы | Поменять роботов, Показать (линии, трассеры), Обнаружение столкновений, Заблокировать положения, Ограничения (скорость, ускорение, сингулярность) |
| ЧЕРТЕЖ | чертежи | Шаблон, Размеры, Аннотации, спецификация (BOM), виды, экспорт и печать |
| ПОМОЩЬ | справка | Помощь, Python API, Python 2.7 |

Над 3D-видом — управление симуляцией: настройки (режим реального и
виртуального времени, время выполнения, повтор, **«Сохранить состояние»**,
уровень точности), сброс, пуск/пауза, часы, скорость, запись PDF, видео,
анимации.

### Встроенные мастера

Готовые Python-команды, которые превращают геометрию в работающее
оборудование, — прямые кандидаты в инструменты агента:

| Команда | Что делает |
|---------|------------|
| `ConveyorWizard` | делает из компонента конвейер: путь, интерфейсы, генератор на входе |
| `EOAT_Wizard` | делает из компонента инструмент робота или внешнюю ось |
| `MachineWizard` | делает из CAD-модели станок для ПЛК или моделирования процессов |
| `PositionerWizard` | позиционер |
| `SensorWizard` | датчик |
| `IO_ControlsWizard` | соединения, управляемые сигналами (зажимы, захваты) |
| `PMAutoLink`, `PMClearLinks`, `PMSetController` | транспортные связи процесса |
| `cmdComponentPattern` | линейный или круговой массив компонентов |

Вызов из кода: `app.findCommand('ИМЯ').execute()`. Часть мастеров
показывает панель с параметрами — это ещё предстоит разобрать.

### Каталог

3078 моделей. Крупнейшие разделы: роботы (1823), позиционеры роботов (232),
позиционеры заготовок (113), инструменты роботов (105), продукты и контейнеры
(95), конвейеры (60), мобильные роботы МП (56), станки (37). Отдельно —
24 шаблона планировок и 52 готовые планировки: у них адрес в папке
`/Layouts/`, и они приносят в сцену целую ячейку.

## Что найдено при обходе

**Сброс схлопывал шаблоны.** Шаблон, вставленный через `app.load()`, после
сброса симуляции сваливался в точку (0, 0, 0): 32 компонента из 34. Так же
вела себя и кнопка «Сброс» в интерфейсе — дело не в агенте. Причина: правки
через Python-API не попадают в «исходное состояние» симуляции, к которому
возвращает сброс. Интерфейс фиксирует его сам («Сохранить состояние»), API —
нет. Решение: мост вызывает `app.Simulation.setInitialState()` после каждой
правки сцены, если симуляция стоит на нуле, а агент ставит модели только на
отметке 0:00:00 и сам сбрасывает симуляцию перед вставкой.

**Часы после сброса.** `app.resetSimulation()` сбрасывает модель, но не часы на
панели. Лечится служебным прогоном на 1 мс и повторным сбросом (см.
`docs/03-protokol-mosta.md`).

**Тип «планировка» в каталоге.** Определялся по расширению `.rpro`, которое у
всех моделей одно; теперь — по папке `/Layouts/` в адресе.

**bridge.json не читался.** Файл был сохранён с BOM, и мост молча работал на
умолчаниях. Теперь читается с `utf-8-sig`.

## Что агент знает и умеет сейчас

- **Справка.** Инструмент `rpro_help` ищет по всей базе знаний и возвращает
  два фрагмента с путём в оглавлении и названия ещё пяти подходящих разделов
  для уточнения. К вопросам «как/где/что такое» агент сам подкладывает два
  фрагмента справки — маленькая модель иначе часто отвечает по памяти.
- **Бытовые слова.** `agent/glossary.py` переводит слова человека в термины
  программы: «трек, рельс» → «внешняя ось, линейная направляющая»; «хваталка»
  → «инструмент, Роботы (инструменты)»; «чтобы детали появлялись» →
  «генератор, Устройства подачи». Им пользуются и справка, и каталог.
- **Каталог.** Поиск больше не требует совпадения всех слов: модели
  упорядочены по числу совпавших слов и очкам, слова сравниваются по основе.
- **Вопрос или поручение.** На вопрос «как сделать…» агент получает только
  читающие инструменты и не может ничего поставить или запустить. Раньше
  8B-модель на такой вопрос ставила модели в сцену сама.
- Прежнее: состояние, сцена, компоненты и свойства, симуляция с перемоткой,
  поиск и вставка из каталога, снимок окна, выполнение Python.

## Чего не хватает до «собери текстом»

По убыванию пользы:

1. **Расстановка.** Модели встают в точку (0, 0, 0). Нужен инструмент
   «поставь X в точку / рядом с Y / в конец конвейера» — через
   `PositionMatrix` и кадры интерфейсов.
2. **Стыковка интерфейсами** («поставь конвейер за конвейером», «надень
   захват на робота») — через `vcSimInterface` и `connectComponents`.
3. **Сигналы** («когда датчик сработал — робот берёт деталь»):
   `vcSignal.Connections`, входы/выходы робота с 100.
4. **Моделирование процессов**: типы деталей, шаги процесса, операторы,
   транспортные связи (`PMAutoLink`). Это основной путь к «собери ячейку
   словами».
5. **Программа робота**: точки и движения через `vcRobotController`,
   `vcRoutine`, операторы робота.
6. **Мастера** как инструменты: конвейер, станок, инструмент робота.
7. **Проверка результата**: статистика, столкновения, пределы суставов.

Каждый шаг — отдельный инструмент с проверкой результата на живой программе,
а не код, который модель пишет в `rpro_exec` сама.

## Ограничения связки «локальная 8B-модель + поиск по словам»

Проверено вопросами новичка. Лучше всего работает то, что закреплено кодом:
запрет правок на вопрос, словарь, подложенная справка. Хуже — связные
объяснения: на «как сделать, чтобы появлялись детали» модель правильно
находит генератор деталей, но смешивает его свойства со свойствами оператора
«Буфер» и выдумывает несуществующий раздел каталога.

Что даст заметный прирост:

- **смысловой поиск (эмбеддинги).** Лексический поиск упирается в словарь:
  страница «Буфер» всплывает на любой вопрос о потоке деталей. Нужна модель
  эмбеддингов на сервере моделей (например, `bge-m3`, около 1,2 ГБ);
- **обрезка истории разговора.** Сейчас история не обрезается, а контекст
  модели — 8 тысяч токенов: длинный разговор вытеснит системную подсказку;
- модель крупнее для сложных поручений — по замерам из
  `docs/04-lokalnye-modeli.md` это вопрос скорости ответа.

## Как пересобрать базу знаний

После обновления R-Pro:

```powershell
# 1. с запущенной R-Pro — карта ленты
powershell -ExecutionPolicy Bypass -File agent\kb_ui_dump.ps1
# 2. справка, API, команды, клавиши → agent\kb\chunks.jsonl
.venv\Scripts\python.exe agent\kb_build.py
```

Проверить поиск: `python agent\kb.py как подключить сигналы робота`.
Установщик кладёт `agent\kb\chunks.jsonl` в сборку и без него не собирается.
