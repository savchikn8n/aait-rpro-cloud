# 17. Базовые навыки из описания агента — кодом

*06.10.2026*

## Проверка до правок: 2 из 17

Описание агента обещает: состояние проекта, состав сцены, координаты, свойства
и поведения компонентов, поиск и выделение, ошибки и предупреждения, запуск,
остановку и сброс симуляции, каталог (найти и добавить), снимок окна для модели
зрения, изменение свойств и операции. Инструменты под всё это были. Прогон 17
живых фраз на запущенной R-Pro (qwen3:8b, 24 инструмента) прошёл **2 из 17**:

| Фраза | Что сделала модель |
|---|---|
| «Запусти симуляцию» | отчёт по линии, настройка линии, проверка линии — 76 с |
| «Поставь длину конвейера 3000 мм» | настройка и отчёт по несуществующей линии — 343 с |
| «Посмотри на экран…» | «я не могу видеть экран» |
| «Добавь в сцену конвейер» | расспросы про станки и изделие |
| «Поставь робота ABB IRB 4600» | починка станции 1 — ошибка |
| «Найди в каталоге робота KUKA» | старое правило «найди» искало посты в сцене |
| «Что сейчас открыто?» | «в R-Pro нет такой функции» |

Плюс «Добавь конвейер» ставил «Спиральный конвейер» — каталог не предпочитал
точное имя.

## Что сделано

**`agent/skills.py`** — навыки из описания разбираются по смыслу фразы и
выполняются кодом (раньше выбора инструмента моделью):

| Навык | Примеры фраз |
|---|---|
| состояние проекта | «что открыто», «что у меня загружено», `/состояние` |
| состав сцены | «какие компоненты в сцене», «сколько моделей», `/сцена` |
| координаты | «где стоит конвейер», «координаты второго конвейера» |
| свойства, поведения | «свойства робота», «какие поведения у конвейера #2» |
| найти и выделить | «найди ленту», «выдели робота ABB» — плюс камера на него |
| ошибки | «есть ошибки?», «что пишет программа», `/ошибки` |
| симуляция | запусти / стоп / сбрось / идёт ли / скорость 5 / «ускорь в 10 раз» |
| каталог | «найди в каталоге KUKA KR 30», `/каталог …`; «добавь конвейер», «поставь робота ABB IRB 4600» |
| снимок и зрение | «что видно на экране», «сделай скриншот», `/снимок` |
| свойство | «поставь длину конвейера 3000 мм», «сделай конвейер подлиннее, метра 4», «измени ConveyorSpeed у конвейера на 300», «скорость 0,5 м/с» (единицы переводятся) |
| операции | «сдвинь робота на 2 м вправо», «поверни конвейер на 90 градусов», «удали второй конвейер», «переименуй конвейер в Лента подачи» |

Как узнаётся компонент: по имени, падежу («ленту» → «Лента подачи»), виду по
поведениям («робот» → «IRB 4600-60/2.05»), номеру («второй конвейер» →
«Конвейер #2»). Несколько одинаково подходящих — агент переспрашивает, а не
правит наугад. Правки — только на 0:00:00 с фиксацией исходного состояния.

Честность: «Запусти симуляцию» в сцене, где нечему работать, R-Pro сама
останавливает через миллисекунду — агент так и говорит, а не «запущена».

**Страховка для фраз, которые код не узнал.** Если в просьбе нет ничего про
линии, цеха, выпуск и стройку, модель получает только 13 базовых инструментов
вместо 24 (`chat.BASIC_TOOLS`). Проверено на 4 нестандартных фразах: 3 верно
моделью (23–35 с), 1 — кодом.

**Каталог** (`catalog.найти`): имя, целиком из слов запроса, — первым; при
равенстве — короче: «конвейер» → «Конвейер».

## Проверка после правок

- 17 живых фраз на R-Pro — **17 из 17**, 0,1–1,5 с (зрение — 15–23 с);
- 60 других формулировок разбора — 60 из 60 после двух правок; 14 «чужих»
  просьб (стройка линии, «как…», «запусти на 3 минуты», «удали всё лишнее»)
  навыки не трогают;
- живая цепочка правок: добавить два конвейера, «второй» — скорость, «первый» —
  переименовать, найти по падежу, удалить — всё верно;
- 30 вопросов «как…» (docs/16) — 30 из 30, не сломались.

## Что ещё не проверено

- Большая сцена (завод на 700 компонентов): разбор имён идёт по всем
  компонентам — скорость там не мерили.
- Удаление вызывает `component.delete()`; отменяется ли оно Ctrl+Z — не проверяли.
