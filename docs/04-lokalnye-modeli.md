# Локальные модели

Проект принципиально работает только на локальных моделях: данные проектов не выходят
за пределы сети предприятия. Среда выполнения — **Ollama**.

## Что требуется от модели

1. **Вызов инструментов (tools / function calling).** Без этого агент не сможет
   обращаться к R-Pro — а это вся суть проекта. Поддержка должна быть именно в Ollama.
2. **Разумная работа с русским языком.**
3. **Понимание Python.** Инструмент `rpro_exec` пишет код на Python 2.7.
4. Отдельно — **модель со зрением** для разбора снимков 3D-вида. Совмещать не обязательно:
   зрение вызывается отдельным инструментом и может работать на другой модели.

## Проверочный стенд (рабочая станция разработчика)

| Параметр | Значение |
|----------|----------|
| Процессор | Intel Core i7-12700KF |
| Оперативная память | 64 ГБ |
| Видеокарта | NVIDIA GeForce RTX 4060 Ti, **8 ГБ видеопамяти** |

Главное ограничение — 8 ГБ видеопамяти. В неё целиком помещаются модели размером
примерно до 7 ГБ в квантовании Q4. Всё, что крупнее, частично считается процессором,
и скорость падает в разы.

## Выбор модели по замерам

Справочнику по сцене не нужна самая умная модель — ему нужна модель, которая
удерживает задачу и отвечает быстро. Проверено на одинаковых вопросах:

| Модель | Время хода | Качество |
|--------|-----------|----------|
| `qwen3:1.7b` | 1–4 с | **негодно**: выдумывает факты не сходив в R-Pro, вместо роботов перечисляет все компоненты подряд |
| `qwen3:4b` | 7–19 с | инструменты выбирает верно |
| **`qwen3:8b`** | **3,6–7,9 с** | инструменты выбирает верно — выбрана по умолчанию |
| `huihui_ai/Qwen3.8-abliterated` (27 млрд) | 40–95 с | хорошо, но неприемлемо медленно |

Восьмимиллиардная быстрее четырёхмиллиардной, потому что целиком помещается в
видеопамять. Модель на 27 млрд в 8 ГБ не влезает: в видеопамяти 3 ГБ из 25,
остальное считает процессор — отсюда полторы-две минуты на запрос.

С учётом двух обращений к R-Pro запрос укладывается в 8–16 секунд.

| Зрение | Время |
|--------|-------|
| Разбор снимка на модели 27 млрд | больше 10 минут — непригодно |
| Первый разбор на `qwen2.5vl:7b` (с загрузкой) | ~56 с |
| Повторный разбор на `qwen2.5vl:7b` | **4 с** |

Отсюда настройки по умолчанию:

- **размышления выключены** (`RPRO_THINKING=0`) — вдвое быстрее, а инструменты модель
  выбирает так же верно. Важная тонкость: выключать их надо пометкой `/no_think`
  в системном сообщении, а **не** параметром `think: false`. Параметр у моделей
  Qwen3 рассуждения не убирает, а перекладывает из отдельного поля прямо в текст
  ответа, и пользователь получает «Хорошо, пользователь спрашивает…» вместо
  ответа. На большой модели это было незаметно, на средних полезло наружу;
- **модель держится в памяти 30 минут** (`RPRO_KEEP_ALIVE=30m`), иначе каждый запрос
  после паузы стоит лишней минуты на загрузку;
- «зрение» вызывается отдельным инструментом и только по надобности — это самая
  дорогая операция по времени.

## Что ставить

```bash
ollama pull qwen3:8b
ollama pull qwen2.5vl:7b
```

Обе влезают в видеопамять целиком. Переключиться на другие можно без правки кода:

```powershell
$env:RPRO_CHAT_MODEL = "qwen3:4b"
$env:RPRO_VISION_MODEL = "qwen2.5vl:7b"
```

## Когда появятся серверы помощнее

Переключение делается одной переменной окружения, менять код не нужно:

```powershell
$env:OLLAMA_URL = "http://<адрес-сервера>:11434"
$env:RPRO_CHAT_MODEL = "qwen3-coder:30b"
```

Ориентиры для выбора под серверную видеопамять:

| Видеопамять | Основная модель | Комментарий |
|-------------|-----------------|-------------|
| 8–12 ГБ | `qwen3:8b` | нынешний вариант |
| 24 ГБ | `qwen3-coder:30b` (архитектура MoE, 3 млрд активных параметров) | быстрая при большом объёме, сильна в коде и вызове инструментов |
| 48 ГБ и больше | `qwen3:32b`, `llama3.3:70b` в Q4 | заметно лучше в длинных рассуждениях |

Для зрения при любом объёме подойдёт `qwen2.5vl:7b`, при запасе памяти — `qwen2.5vl:32b`.

## Настройка агента

| Переменная | Назначение | По умолчанию |
|------------|------------|--------------|
| `OLLAMA_URL` | адрес Ollama | `http://127.0.0.1:11434` |
| `RPRO_CHAT_MODEL` | основная модель | `qwen3:8b` |
| `RPRO_VISION_MODEL` | модель зрения, пустая строка выключает | `qwen2.5vl:7b` |
| `RPRO_THINKING` | режим размышлений моделей Qwen3 | `0` (выключен) |
| `RPRO_KEEP_ALIVE` | сколько держать модель в памяти | `30m` |
| `RPRO_NUM_CTX` | размер контекста в токенах | `8192` |
| `RPRO_MAX_TOOL_STEPS` | предел вызовов инструментов на один запрос | `8` |
| `RPRO_ALLOW_EXEC` | разрешить выполнение Python внутри R-Pro | `1` |

## Замечания по поведению моделей

- **Рассуждающие модели семейства Qwen3** склонны к длинным размышлениям перед ответом.
  Если ждать приходится слишком долго, помогает явная просьба в запросе отвечать кратко.
- **Модели меньше 7 млрд параметров** часто путаются при вызове инструментов: придумывают
  несуществующие имена или забывают обязательные аргументы. Ниже 7B опускаться не стоит.
- **Ошибки инструментов возвращаются модели текстом.** Это сделано намеренно: модель видит
  сообщение вроде «компонент не найден» и может исправиться сама, вызвав поиск.

## Автопереключение на сервер предприятия (14.10.2026)

Агент выбирает модель сам (`agent/llm_ollama.py`): сначала локальная Ollama (`OLLAMA_URL`, по умолчанию
`127.0.0.1:11434`), а если она не отвечает — запасные адреса `OLLAMA_FALLBACK_URLS` (по умолчанию
`https://rpro.itc.kl.avtotor.ru/ollama` — Ollama предприятия, там `qwen3:8b` и `qwen3.5:9b` с зрением и
контекстом 262k). Проверка адреса — раз в минуту и при обрыве; на выезде достаточно VPN в сеть предприятия
(R-Pro и так нужен сервер лицензий). Если нужной модели на сервере нет, берётся лучшая с инструментами
(для зрения — с `vision`). Где сейчас модель — в `/health` (`model_source`).
Замеры 14.10 с рабочей станции: выбор запасного адреса 2,3 с; простой ответ 12 с, ответ с вызовом
инструмента ~27 с (сервер общий; локальная карта быстрее). Отключить запасные: `OLLAMA_FALLBACK_URLS=`.
Полностью без сети предприятия (интернет/командировка без VPN) агент остаётся без модели — команды `/…`
кодом (справка, курс, состояние) работают и так; облачную модель см. docs/19-plan-fleshka-i-oblako.md.
