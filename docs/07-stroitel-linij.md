# Строитель производственных линий и доктор линии

Агент собирает по одной фразе работающую производственную линию: подача
деталей, конвейеры змейкой через цех, станции «робот + станок», контроль,
финишный робот и выход. После запуска симуляции детали идут по линии, а роботы
загружают и разгружают станки. Найденные потом ошибки агент чинит правкой
одной станции, не пересобирая линию.

| Файл | Где выполняется | Что делает |
|------|-----------------|------------|
| `agent/hands27.py` | внутри R-Pro (Python 2.7) | «руки»: загрузка, расстановка, стыковка, робот на контроллер, маршрут, связи, камера, диагностика и правки |
| `agent/line_builder.py` | в агенте (Python 3) | планировщик: змейка по цеху, станции, самопроверка |
| `agent/line_doctor.py` | в агенте | проверка линии и точечные правки |

Инструменты агента: `rpro_build_line`, `rpro_line_check`, `rpro_line_fix`.

## Как устроена линия

Логика — штатное моделирование процессов R-Pro (как в шаблонах программы), а
не самописные скрипты:

```
Устройство подачи → конвейеры → «С конвейера» (Съём N)
      → робот («ТК робота») → станок (процесс станка) → робот
      → «К конвейеру» (Укладка N) → конвейеры → … → Съём финиш → робот → Выход
```

- **Маршрут деталей** — последовательность процессов в `FlowTable2`:
  `Съём 1, <станок 1>, Укладка 1, Съём 2, …, Съём финиш, Выход`.
- **Транспортные связи** — `TransportSystem.createTransportLink`: робот
  станции везёт «Съём N → станок → Укладка N». Между укладкой и следующим
  съёмом деталь едет по конвейеру физически, связь не нужна.
- **Уникальные имена процессов.** Все «С конвейера» по умолчанию —
  один процесс; строитель сразу после загрузки переименовывает реализацию
  (свойство `Name` процедуры), иначе маршрут не различит станции.

## Геометрия

- Ряды змейки вдоль X, развороты двумя поворотами по 90° (`Direction`
  Left/Right) и прямым участком 5 м: ряды в 7 м друг от друга.
- Станция разрывает ленту на 1,8 м: съём в конце участка, укладка — дальше
  по ходу. Робот — посередине, в 1,3 м сбоку, станок — за роботом.
- Станок ставится лицом к роботу по кадру `ResourceLocation`: его ось X
  смотрит от обслуживающего на станок. Разворачиваем по повороту кадра, а не
  по направлению на него — у Colchester кадр сдвинут вбок.
- В нечётных рядах станции сдвинуты на полшага, чтобы оборудование соседних
  рядов не вставало в столбец.
- Стыковка — как кнопка PnP: компонент ставится так, чтобы кадр его
  интерфейса лёг на кадр партнёра, затем `interface.connect()`.

## Станки и роботы

Отобраны прогоном всех 37 станков каталога и проверкой на живой линии:
процесс должен начинаться с «Транспорт В (от предыдущего процесса)».

| Вид | Модели |
|-----|--------|
| фрезерный | Haas VF-1, Haas UMC-500, Hurco VM-1, Feeler VMP-32A, Tongtai TVL-40, фрезерный ЧПУ R-Про |
| токарный | Haas ST-30, Goodway GA-2000, Feeler FTC-350, токарный ЧПУ R-Про |
| контроль | Mapvision Quality Gate, координатно-измерительная машина |
| прочие | пятиосевой, портальный, рабочая станция |

Не подходят: 3D-принтер, термопластавтоматы, EffiMat — сами рождают детали
(источники, а не станции); Colchester 3000L и лазерная резка — место
загрузки дальше досягаемости робота (2771 мм у Colchester).

Роботы — все с досягаемостью ~2,05–2,1 м: ABB IRB 4600-60/2.05, KUKA KR 30
R2100, FANUC M-710iC/50, Yaskawa GP50. По умолчанию марки чередуются.

## Доктор линии: чинить, а не пересобирать

Структура линии не хранится у агента — она восстанавливается из данных
программы (маршрут и связи), поэтому доктор работает и с линией, сохранённой
раньше.

- **Проверка** (`rpro_line_check`): по каждой станции — расстояние от плеча
  робота до съёма, станка и укладки; ошибки прогона из панели вывода,
  привязанные к станции по имени робота или процесса. Порог — 1850 мм
  (рабочие станции дают 1193–1665).
- **Правки** (`rpro_line_fix`): подвинуть станок ближе, заменить модель
  станка (маршрут и связи переписываются на новую), сменить робота, время
  обработки, либо `auto` — всё найденное: сдвиг, а если его мало — замена.
- Строитель вызывает доктора сам после стройки.
- Любая правка — только на отметке 0:00:00, иначе сброс её откатит.

Проверено: на станцию 8 намеренно поставлен Colchester; доктор нашёл
2771 мм, сдвиг на допустимые 450 мм не помог, и он заменил станок на Haas
ST-30. Затем прогон 600 с на всех десяти роботах без единой ошибки.

## Двухэтажный цех со связанными процессами

`agent/plant_builder.py`, инструмент `rpro_build_plant`:

```
1-й этаж:  линия A: подача → станция → спираль вверх
           линия B: подача → станция → спираль вверх
2-й этаж:  A: станция → поворот к центру ─┐
                                          ├─ общий робот → общий контроль качества
           B: станция → поворот к центру ─┘          ↓
                                общая лента → скат вниз
1-й этаж:  общая отгрузка: финишный робот → выход
```

- Подъём — «Конвейер спиральный тип 2» (`HeightOffset` = отметка этажа,
  3 м). Вниз спираль не годится: `Elevation=Down` кадры не перестраивает,
  нужна кнопка `Rebuild`, которую из API не нажать. Спуск — «Конвейер
  наклонный» с `OffsetDirection=Down` (7,5 м на 3 м).
- Ленты второго этажа — обычные конвейеры с `ConveyorHeight` = 3700 мм:
  стоят на полу на длинных ногах, как эстакада. Узлы съёма и укладки
  поднимаются тем же свойством.
- Перекрытие — «блок» (`Length_X`, `Width_Y`, `Height_Z`; кладётся центром),
  опоры — «Столб (прямоугольный)» по сетке ~6 м, лестница «Stairway v2» с
  `HeightOffset` = отметке. Роботы и станки второго этажа стоят на нём.
- Связанность: у A и B свои группы деталей и маршруты, но хвост маршрута
  общий — один процесс контроля, одна укладка, один финиш. Транспортные
  связи общих шагов созданы для обеих групп; общий робот видит оба потока.

Проверено прогоном 420 с (x3): обе линии поднимаются к 72-й секунде, детали
обеих проходят общий контроль, спускаются и сдаются на общий выход, ошибок
нет. Агент на qwen3:8b собрал такой цех сам по фразе «Собери двухэтажный
цех: внизу две линии — токарка и фрезеровка, наверху ещё по станку, в конце
общий контроль качества для обеих линий» — и он так же отработал.

Ограничения: линии A и B должны иметь одинаковое число станций на каждом
этаже (иначе их концы не сойдутся к хабу по X); одна общая станция; этаж
один — 3 м.

## Несколько линий в одной сцене

Новая линия встаёт за северной границей уже построенного — строитель ничего
не удаляет, если его не попросили очистить сцену. У каждой линии:

- своё пространство имён процессов: «Л2 Съём 1», «Л2 Haas VF-1 1»;
- своя группа деталей «Линия N» и свой тип детали «Деталь ЛN»;
- свои транспортные связи (связь привязана к группе и после создания не
  меняется — при переносе её пересоздают).

Номер станции у доктора — «2.5» (линия 2, станция 5), если линий несколько.

Так было не сразу. Вторая линия с теми же именами процессов слилась с
первой: 27 процессов по две реализации, общий тип детали (коробки поехали и
по первой линии) и один маршрут на двоих. Исправлено правкой, без удаления:
`hands27.split_lines` развёл процессы по линиям (по положению подачи), дал
второй свою группу и тип детали, пересоздал её связи и записал обеим
маршруты, восстановленные по связям. Проверено прогоном: три линии в одной
сцене, 31 станция, ошибок нет.

## Ловушки программы (найдены по дороге)

- **`isinstance()` на объекте R-Pro отравляет интерпретатор.** Он лезет в
  `__class__`, получает исключение, и даже пойманное, оно остаётся «висеть»
  и всплывает на следующей операции с ложным номером строки (падал
  `for pid in pids`). Тип проверять только через `type(x) in (str, unicode)`.
  То же с `obj or default` — проверка истинности объекта; только `is None`.
- **Сеттеры свойств R-Pro принимают байты UTF-8.** Юникод с кириллицей
  отвергается невнятной `SystemError`; `u'Л1 …'.encode('utf-8')` проходит.
  Имя процесса меняется свойством `routine.getProperty('Name')` — только у
  этой реализации (групповое `changeGroupId` переименовало бы все линии).

- `app.load()` иногда бросает `SystemError`, хотя компонент загрузился.
- Компоненты МП не переименовываются (`SystemError`) — ведём их по
  выданным программой именам.
- `vcMatrix.translateAbs` прибавляет смещение, а не ставит позицию.
- Мировые матрицы пересчитываются только на шаге симуляции: у только что
  поставленного компонента `WorldPositionMatrix` — прежняя. Положение узла
  считаем относительно компонента по прежним матрицам.
- Интервал генератора — свойство `RealDistribution`, принимает число, а не
  строку; доступ через `SingleFeed.getProperty('Interval')`.
- Кириллица из агента приходит в Python 2.7 байтами, из программы —
  юникодом: сравнивать только после приведения (`_u`).
- Старая `FlowTable` этой версией не читается — маршрут в `FlowTable2`.
