# Задача: исправить русские уроки по исходному тексту

Это единственная инструкция. Вы исправляете несколько русских уроков (база знаний ИИ-агента для
R-Pro — российской сборки Visual Components 4.x со скриптами на Python 2.7). Уроки сделаны
моделью Haiku из видео и PDF-мануалов Visual Components Academy; независимый аудит нашёл в части
из них придуманные «ловушки», перепутанные кнопки, потерянные шаги, искажённые имена. Ваша
работа — исправить урок так, чтобы каждое утверждение подтверждалось исходным текстом.

Рабочая папка: `C:\Users\savchikav\Documents\aait-rpro\agent\academy`.

## Что вам дано

Вам назвали пачку — JSON-массив slug в `work/fix/batches/<id>.json`. На каждый slug есть файл
`work/fix/in/<slug>.txt` из трёх частей:

1. **Замечания независимого аудита** (если урок аудировался): «Unsupported» — чего нет в источнике,
   «Wrong» — что неверно, «Missed» — важное, что потеряно, «Terminology», «Danger for the assistant»,
   «Verdict» со списком правок. Если аудита нет — сказано, какие идентификаторы из раздела
   «Скрипты и API» не найдены в исходнике; тогда проверьте **весь** урок сами.
2. **Текущий русский урок** (то, что получает агент).
3. **Исходный текст** — единственная истина: транскрипт видео (минутные метки `[3:20]`, это
   распознанная речь, код в ней «прочитан вслух») или текст PDF-мануала (метки страниц `[стр. 12]`).

## Порядок работы

1. Одним ответом (параллельные Read) прочитайте этот файл, пачку и все `work/fix/in/<slug>.txt` пачки.
2. Для каждого урока сверьте утверждения урока с исходником и подготовьте исправленный урок.
3. Одним ответом (параллельные Write) запишите для каждого урока:
   - `work/fix/out/<slug>.md` — исправленный русский урок (весь файл целиком);
   - `work/fix/out/<slug>.log` — одна-две строки: что изменено и что осталось под сомнением.
4. Ответьте только строками `<slug>: <сколько правок> | сомнение: да/нет`.

## Правила исправления

- **Только то, что есть в исходнике.** Удалите всё, чего источник не подтверждает (придуманные
  «Ловушки», числа, шаги, имена). Нельзя добавлять факты из собственных знаний, даже если уверены.
  Нельзя «чинить» имена API по памяти: регистр имён Python-API исправляется автоматически по
  справочнику, пишите имена так, как они в исходнике или как их называет докладчик.
- **Исправьте неверное** (не та кнопка, не тот порядок, не то значение) строго по исходнику.
- **Верните важное** из «Missed» и из списка правок аудита — кратко, одной строкой, с точными
  названиями из исходника. Не раздувайте урок.
- Идентификатор из **видео**, восстановленный из речи и не произнесённый по буквам, пишите в обратных
  кавычках с пометкой «(восстановлено на слух, не проверено)». В PDF имена точные, пометка не нужна.
- **Применимость к R-Pro.** R-Pro основана на Visual Components 4.x; версия базы неизвестна точно.
  Если аудит или исходник указывают на возможность версии выше базовой (5.x, Python 3 API, новые
  свойства 4.8–4.10) — в строке «Применимость к R-Pro» пишите «проверить: <причина по-русски>».
  Не пишите «скорее всего работает» без оснований.
- **Терминология.** Русские названия элементов интерфейса R-Pro, уже стоящие в уроке в «ёлочках»,
  не меняйте, если аудит не назвал их неверными. Нового названия в уроке нет — переведите по смыслу
  и один раз добавьте английский оригинал в скобках: «Слой (Layer)». Не выдавайте придуманное
  русское название за точное. Если аудит указал на смесь языков, приведите к одному виду.
- **Формат — прежний, строго:**
  `# Название` / строка `Источник: … Применимость к R-Pro: …` / `## Задача` / `## Как сделать` /
  `## Скрипты и API` (только если есть что писать; иначе раздел не нужен совсем, не пишите «Нет.») /
  `## Лайфхаки и ловушки` (строки «- Совет:» и «- Ловушка:») / `## Ключевые слова` (12–20).
  Метки времени `[m:ss]` и страниц `[стр. N]` в уроке не нужны.
- **Длина — до 2800 знаков.** Считайте знаки, а не байты (кириллица — два байта на знак). Не
  помещается — режьте очевидные шаги, но не лайфхаки и не ловушки, подтверждённые исходником.
- Если после проверки правок не требуется — перепишите файл как есть и в `.log` напишите «правок нет».
- Если урок по сути не нужен (аудит: «drop», материал целиком про функцию, которой в R-Pro быть не
  может, и исправлением это не лечится) — **не создавайте** `.md`, а в `.log` напишите
  «ПРОПУЩЕН: причина».

## Границы
