# Лайфхаки R-Pro — часть 2

Пометка ⚠ означает, что урок помечен `check` (функция может отсутствовать в R-Pro 4.x) либо относится к внешнему порталу/ПО, которое у R-Pro может отличаться.

## Интерфейс и навигация

- Ctrl+F — самый быстрый способ вместить всё в вид, когда потерялись в 3D; если облако точек или геометрия «пропали» после импорта, помогает «Заполнить всё». [navigation, import-point-cloud]
- В 2D-мире чертежа камера не вращается — доступны только панорама и масштаб. [navigation]
- Режим приближения «Удерживать центр интереса» не даёт пролететь сквозь сфокусированный объект (удобно в тесных местах при программировании робота), но центрирование на пустой пол в нём не работает — только на объекты; выбранный режим сохраняется в параметрах. [navigation-zoom-mode]
- Двойной клик по плитке селектора вида разворачивает камеру на 180° в противоположный вид; клик по рёбрам и углам селектора даёт промежуточные углы. [navigation-view-selector]
- Чтобы выбрать компонент внутри группы, сначала выберите группу, затем кликните по компоненту; если кликнуть по компоненту без предварительного выбора группы, выделение снимется. [group-and-ungroup-components]
- Группы удобны для массового изменения свойств (например, у набора конвейеров). [group-and-ungroup-components]
- Shift+клик быстро активирует инструмент «Привязка»/«Выравнивание» с предпросмотром без обращения к меню. [import-and-export-floorplans]
- Подпланировки: объединённые макеты автоматически становятся подпланировками, у каждой свое начало координат; CAD-данные (планы этажей) держите в отдельной подпланировке, чтобы легко удалить их перед передачей макета третьим лицам. [managing-larger-simulations-with-sub-layouts]
- Скрывайте подпланировки при записи анимации и показе клиентам; скрытие влияет только на эту подпланировку и не удаляет компоненты из модели (на них можно ссылаться). [managing-larger-simulations-with-sub-layouts]
- В каталоге серверные (удалённые) источники можно давать коллегам, они обновляются автоматически — удобно для общих библиотек. [how-to-use-ecatalog-panel]
- В каталоге в режиме «подробности» добавьте столбец даты изменения и сортируйте по убыванию, чтобы увидеть обновлённые компоненты; ПКМ по заголовку открывает настройку столбцов и метаданных (описание длинное — столбец можно скрыть). [how-to-use-ecatalog-panel]
- Префиксы сигналов IN/OUT чувствительны к регистру — пишите ПРОПИСНЫМИ; 0 читается как false, 1 как true. «Булевая карта» есть только в версиях Professional/Premium. [new-io-groups-and-using-signals-as-condition-variables]
- Группам сигналов давайте понятные имена вместо номеров; панель сигналов можно закрепить кнопкой блокировки. [new-io-groups-and-using-signals-as-condition-variables]
- ⚠ Панель вывода (запись 5.0): поиск по регулярным выражениям, отключение «Дублирующихся сообщений» и временные метки помогают отлаживать; большой объём отладочных сообщений тормозит панель — выключайте режим отладки после работы. [output-panel]

## Моделирование компонентов

- Для геометрии из CAD: «Select Identical» с «Feature level» считает всю связную геометрию одним объектом, «Geometry Set» — каждый набор отдельно. [geometry-feature-tools-for-component-modeling]
- «Collapse» сбрасывает матрицу позиции элемента в начало компонента, визуально геометрия остаётся на месте. [geometry-feature-tools-for-component-modeling]
- «Remove Holes» может закрыть отверстия снизу, а не удалить полностью — сначала разделите геометрию «Slice». [geometry-feature-tools-for-component-modeling]
- «Merge Faces» применим только к уже объединённой геометрии; отдельные примитивы не склеиваются. [geometry-feature-tools-for-component-modeling]
- Если импортированная геометрия выглядит темнее на краях, это отражённые нормали — примените «Invert». [geometry-feature-tools-for-component-modeling]
- Параметрическая CAD-модель: отрежьте торцевые крышки, чтобы масштабировать среднюю секцию независимо без искажений; предварительно измерьте геометрию (инструмент «Измерение»), чтобы точно задать параметры. [geometry-feature-tools-for-component-modeling]
- Импортируйте геометрию командой Import, а не перетаскиванием — иначе она не центрируется правильно. [model-a-turn-unit]
- При перетаскивании геометрии на узлы держите Shift — позиция сохранится; без Shift геометрия смещается. [model-an-articulated-robot]
- Выключите видимость рамок перед «Freeform Selection», иначе рамки попадут в выделение и вызовут ошибки. [model-an-articulated-robot]
- Для сочленённого робота берите шаблон того же производителя и серии; сохраняйте компонент несколько раз подряд для резервных копий. [model-an-articulated-robot]
- Перед импортом тяжёлой геометрии оцените сложность («Analyze» / «Count triangles»), чтобы решить, нужно ли упрощать. [modeling-a-workpiece-positioner, model-a-robot-gripper-part-i]
- Origin звеньев позиционера должен лежать на оси вращения, а не внизу детали, иначе поворот будет неправильным; при неверной кинематике сделайте Reset simulation и поправьте origin в режиме Move. [modeling-a-workpiece-positioner]
- Режим Selected в группе Move сдвигает origin, не двигая геометрию; Shift при привязке снапит к краям и центрам. [modeling-a-workpiece-positioner]
- Сервоконтроллер общий для нескольких соединений: создайте на E1 и переиспользуйте на E2. [modeling-a-workpiece-positioner]
- Используйте Positioner wizard — он создаёт интерфейс монтажа (mount frame); внешние оси появляются в панели джога только после подключения позиционера через Interfaces. [modeling-a-workpiece-positioner, modeling-robot-positioner]
- Трансляционные соединения по умолчанию идут по оси Z — меняйте на локальную X; если мотор не двигается вместе со слайдером, он не входит в Link 1 (перетащите его туда с Shift). [modeling-robot-positioner]
- Материалы назначайте в два этапа: сначала конкретные (сталь, чёрный), затем материал уровня компонента как запасной. [modeling-robot-positioner, modeling-a-workpiece-positioner]
- Для центрирования трека установите X и Y компонента в ноль; Ctrl при перетаскивании стрелок оси даёт привязку к элементам геометрии. [modeling-robot-positioner]
- Для захвата используйте End Effector Wizard: он создаёт TCP, логику захвата и сигналы; TCP ставьте между пальцами или в центре зажимной поверхности. [model-a-robot-gripper-part-i]
- «Transitional follower» синхронизирует второй палец с первым без отдельного управления; диапазон хода проверяйте интерактивно в режиме Interact, затем вводите значения. [model-a-robot-gripper-part-i]
- Если движение захвата выглядит неверно, проверьте стрелки направления осей соединений в режиме Move. [model-a-robot-gripper-part-i]
- Если захват не зажимает деталь, проверьте Actions → Configuration: TCP-инструмент должен быть назначен выходному сигналу; без выходного сигнала деталь не поднимется. [model-a-robot-gripper-part-ii]
- После команды захвата ставьте Wait, чтобы движение завершилось до движения робота; значение Close можно подбирать на лету в джоге под разную толщину заготовок. [model-a-robot-gripper-part-ii]
- Крепление инструмента: привязывайте собственный фрейм инструмента к фрейму фланца snap'ом; порядок — сначала физически соединить, потом обучить захват, потом крепление/снятие. [mount-and-dismount-tools]
- Значения внешних суставов сохраняются в операторах движения и при смене инструмента должны задаваться явно; если робот импортирует сустав инструмента, он окажется в каждом операторе. [mount-and-dismount-tools]
- Для пластин захвата включите «Останавливать при ограничении»; база 2 — для операций со стороны поддона, база 1 — для подачи деталей. [mount-and-dismount-tools]
- Состояние конфигурации инструмента сохраняйте через Settings > Save State. [mount-and-dismount-tools]
- Ротационный стол: сустав вешайте на извлечённый (Extract) узел, родитель остаётся неподвижным; enter_frame/exit_frame создавайте в корневом узле, чтобы они не вращались; имена рамок уникальны в пределах компонента. [model-a-turn-unit]
- Ротационный стол: capacity пути = 1 против столкновений, `path.enabled = false` запрещает вход новых деталей во время поворота; для синхронизации используйте center_signal и exit_signal. [model-a-turn-unit]
- После джога робота или сброса симуляции сустав ротационного стола возвращается в ноль; сначала проверьте интерфейсы (должны защёлкиваться), потом добавляйте скрипт. [model-a-turn-unit]
- Объёмный датчик: если не срабатывает, проверьте, что задан detection_container и выбран метод; BBox-тесты (Intersect / Center Inside / Fully Inside) срабатывают при разном положении детали, для соседних узлов нужен «test siblings». [model-a-volume-sensor]
- Объёмный датчик: «Precise» проверяет реальную геометрию (точнее всего); интервал выборки (по умолчанию 0,01 с) — чем меньше, тем выше нагрузка на CPU; смещение рамки задаёт глубину, иначе объём — плоскость. [model-a-volume-sensor]
- Питатель продукта: у Advanced Feeder в режиме распределения веса суммируются (2 и 3 → 40% / 60%); из пути удалите Sensor Interface и Path Frame 1. [model-and-configure-a-product-feeder]
- Питатель, режим таблицы: времена только по возрастанию (10 затем 2 даст ошибку); таблица воспроизводится один раз — для цикла берите batch или single; Excel-файл должен быть закрыт при импорте. [model-and-configure-a-product-feeder]
- Шарнир, фиксированный: все ограничения (twist, swing X/Y) «locked»; для действия гравитации и сил тип физики звена — «В Физике», а не kinematics. [model-a-fixed-joint]

## Свойства и скрипты (Python)

- При нажатии «Компилировать» выполняется только код в глобальной области; код внутри `OnRun()`, `OnStart()` и т. п. нет. [introduction-to-python-api-2-7]
- После изменения свойств из кода (например, `sphere.visible = False`) вызывайте `comp.rebuild()` и `app.render()`, иначе 3D-вид не обновится. [introduction-to-python-api-2-7, joints-and-degrees-of-freedom]
- Только `OnRun()` может тратить время симуляции (`delay()`, движение servo, блокирующие вызовы); остальные обработчики не могут. [introduction-to-python-api-2-7]
- Основной цикл — `while sim.IsRunning:` в `OnRun()`, внутри обязательно задержки или ожидание сигнала, иначе симуляция блокируется. [introduction-to-python-api-2-7]
- Перед `createProperty()` проверяйте `if comp.getProperty('name') is None:` — иначе ошибка дублирования свойства. [introduction-to-python-api-2-7]
- Ctrl+D дублирует строку; перетаскивание элемента из диаграммы компонента в редактор генерирует getter, с Shift — более умный код. [introduction-to-python-api-2-7]
- `comp.children` возвращает только первый уровень — для всей иерархии нужен рекурсивный обход. [joints-and-degrees-of-freedom]
- Присоединённые компоненты (трасса, инструмент) имеют собственные деревья узлов и не попадают в `get_all_nodes()`. [joints-and-degrees-of-freedom]
- У внутренних суставов `external_controller == None`, у внешних — ссылка; внешние суставы двигайте через `robot_controller.joints`, внутренние — через DOF; DOF корневого узла всегда None — отфильтруйте. [joints-and-degrees-of-freedom]
- Значение сустава вне лимитов (например, 500°) вызывает предупреждение; после установки суставов вызывайте `get_application().render()`. [joints-and-degrees-of-freedom]
- Оператор Прикрепить к пути конвейера: при нескольких прикреплённых коробках последняя прикреплённая идёт первой в списке — обходите циклом `for`, а не берите `[0]`. [how-to-attach-objects-to-conveyor-paths]
- Датчики, прикреплённые к конвейеру, тоже захватываются путём — исключайте их list comprehension. [how-to-attach-objects-to-conveyor-paths]
- Если коробки не едут после прикрепления, проверьте, что скрипт скомпилирован и имя пути точно совпадает с именем в диаграмме компонента. [how-to-attach-objects-to-conveyor-paths]
- Для компонентов из библиотеки используйте «Клонирование», а не копирование-вставку: оно реплицирует присоединённых детей и поведения. [how-to-attach-objects-to-conveyor-paths]
- Серво-толкатель: min = max = 0 блокирует движение; максимум = ширина конвейера минус ширина толкателя. [how-to-attach-objects-to-conveyor-paths]
- Расширение на C# (подсветка динамических компонентов): вызывайте `Clear()` на списках материалов перед заполнением; списки материалов и компонентов должны быть одной длины и порядка; подключайтесь к `SimulationStarted` для восстановления материалов после перезапуска. [highlight-dynamic-components]
- Динамические компоненты могут быть удалены во время симуляции — синхронизируйте списки осторожно. [highlight-dynamic-components]

## Process Modeling: потоки, ресурсы, операторы

- Шаги потока и связи транспорта — разные вещи, нужны оба; разорванные связи показаны красным X, каждую нужно определить; без связей детали не потекут. [introduction-to-flows-and-transportation, introduction-to-process-modeling, introduction-to-using-resources]
- Дублирование компонентов не добавляет шаги потока автоматически — добавляйте вручную. [introduction-to-flows-and-transportation]
- Копирование операций на вкладке «Главная» с последующим добавлением шагов отдельно предотвращает случайное создание потока; «Фильтр транспортных ссылок» показывает маршруты выбранной операции. [introduction-to-flows-and-transportation]
- Интерполяция двигает детали по прямым и не учитывает препятствия — для сложных путей берите управляемый транспорт (контроллер робота). [introduction-to-flows-and-transportation]
- Видимость связей транспорта зависит от выбранной группы процессов; добавление связи при неверно выбранной группе не чинит разрывы в другой. [introduction-to-using-resources]
- Группа процессов должна быть выбрана перед добавлением шагов; у группы может быть только один путь потока, для других маршрутов создавайте новые группы; тип детали принадлежит ровно одной группе. [introducing-a-new-flow-group, introduction-to-process-modeling]
- Тип детали без ссылки на компонент невидим в симуляции; тип вне группы процессов с шагами потока не маршрутизируется. [introduction-to-product-types]
- Удаление компонента в 3D не удаляет определение детали в Редакторе типов. [introduction-to-product-types]
- «Изменить тип» ставьте после оператора «Время обработки»; целевые типы должны уже существовать в Редакторе типов. [introducing-a-new-product, introduction-to-process-statements]
- «Изменить тип» может заодно удалять присоединённые детали, оставляя основную — это упрощает модель. [introduction-to-process-statements]
- Start Transport In не берёт из контейнера, только из предыдущей операции. [introduction-to-process-statements]
- При присоединении деталей Transport Out блокируется, пока не придут все; без согласованного Transport Out «заблудившиеся» детали остаются. [introduction-to-process-statements]
- Перед Attach ставьте Wait Transport, чтобы гарантировать приход детали; для нескольких входов дублируйте Transport In. [introduction-to-process-statements, introducing-a-new-flow-group]
- Фильтры деталей в Transport In вычисляются во время симуляции — для проверки включайте/выключайте группы процессов. [introduction-to-process-statements]
- Операторы «Получить свойство» и «Ждать состояния» вместе дают синхронизацию по состоянию конвейера; если условие никогда не выполнится, симуляция зависнет на этом операторе. [get-property-and-wait-property-condition-statements-in-process-modeling]
- В сборках Order Index управляет порядком прихода: детали с одинаковым индексом приходят вместе в порядке доступности. [how-to-complete-an-assembly-or-disassembly-task]
- Операторы выполняются сразу, как только готовы — для управления скоростью создания сборки используйте Delay. [how-to-complete-an-assembly-or-disassembly-task]
- Режим Process Assembly в Transport Out обрабатывает несколько слотов одним оператором. [how-to-complete-an-assembly-or-disassembly-task]
- Product Filters первой детали сборки не копируются на дубликаты, созданные паттерном добавления слотов; имена локальных переменных в операциях независимы. [how-to-complete-an-assembly-or-disassembly-task]
- Чтобы не добавить лишних шагов, открывайте редактор ПКМ по подписи операции; при удалении шагов транспортные связи удаляются отдельно. [how-to-complete-an-assembly-or-disassembly-task]
- Тип сборочного изделия не то же самое, что компонент-сборка в 3D-мире; для навигации в библиотеке используйте фильтры «parts»/«assemblies». [introduction-to-assemblies-2]
- Процессные генераторы создают типы деталей автоматически; стандартные генераторы из папки Feeders с процессными потоками не интегрируются. [introducing-feeders-an-overview]
- Advanced Feeder принимает CSV и вероятностные распределения, Shape Feeder переключает типы без перенастройки процессов. [introducing-feeders-an-overview]
- Палетизация через TransportPatternIn: присоединение не происходит автоматически — добавьте явно, иначе деталь не поедет с поддоном; при ошибке «потеряно состояние детали» переименуйте переменную и добавьте присоединение. [palletize-using-pm-transportpatternin-statement]
- Смещения паттерна берутся из системы координат родителя (поддона); шаг важен только при количестве > 1. [palletize-using-pm-transportpatternin-statement]
- Для сборочной палетизации переключите контроллер с «Интерполирующего» на «Робот» или «Человек». [palletize-using-pm-transportpatternin-statement]
- Контроллеры роботов подключаются напрямую один-к-одному; контроллеры людей и мобильных роботов — удалённо через Interfaces. [introduction-to-using-resources]
- Смещение приближения (X, Y, Z) задаёт позицию подхода: X=0 прямо над деталью, X=200 — сбоку. [introduction-to-using-resources]
- Load/Unload Assist: на контроллер человека или робота; frame с именем `assist_location` — точка захвата/доставки помощника; если досягаемости не хватает, панель вывода выдаёт ошибку — уменьшите смещение по Y. [load-and-unload-assist-by-using-another-resource]
- Ёмкость мобильного робота определяет число перевозимых деталей. [load-and-unload-assist-by-using-another-resource]
- Зарядка мобильных роботов: для проверки немедленной зарядки Initial Capacity ставьте ниже Recharge Limit; Recharge Limit и Charge To — проценты, а не ёмкость. [idling-and-charging-of-resources]
- Если Power выключен, робот работает вечно — для проверки логики зарядки включите; Allow Idling выключен — робот уходит сразу по достижении Charge To; слишком большой Approach Distance впустую тратит время. [idling-and-charging-of-resources]
- Initial Capacity можно задать распределением, чтобы начальный заряд варьировался. [idling-and-charging-of-resources]
- Conveyor Wizard автоматически добавляет Statistics и Path behavior; Path имеет plug-and-play и интерфейс датчика. [make-a-simple-conveyor-plc-ready]

## Роботы и программирование (OLP)

- Multi-Grasp включайте до обучения; без него робот берёт одну деталь из пакета; если берёт только одну — увеличьте X-размер объёма захвата. [grasp-and-release-multiple-objects]
- Для подхода/отхода используйте PTP, для захвата/укладки — линейное движение. [grasp-and-release-multiple-objects]
- Гравитация при отпускании — допуск обнаружения столкновения: деталь движется вниз до касания и приклеивается; для плоской поверхности хватает 1–10 мм. [how-to-use-gravity-direction, grasp-and-release-multiple-objects]
- Слишком большая гравитация проводит деталь сквозь цель (например, до конвейера под поддоном) — сначала измерьте реальную толщину цели (лист 10 мм), а не повышайте значение; для стопок берите разные выходные сигналы с разной гравитацией. [how-to-use-gravity-direction]
- Для цикла программы робота различайте «программа циклируется» и «повторять» (перезагрузка симуляции). [how-to-loop-a-robot-program]
- При включённом «программа циклируется» переменные процедуры основной программы не сбрасываются — получается вечный цикл; ставьте сброс присвоения в конец главной программы либо используйте переменные подпрограммы (они сбрасываются при каждом вызове). [how-to-loop-a-robot-program]
- Если TCP инструмента задан неверно, захват будет в неправильном месте (например, внутри ящика); TCP в операторе движения должен совпадать с назначением инструмента в конфигурации действий. [introduction-to-robot-teaching]
- Кнопка touch-up в режиме джога привязывает точку к текущей позиции робота; режим Move позволяет править точки без живого джога; замена робота сохраняет точки программы. [introduction-to-robot-teaching]
- Палетизация: определите базу в начале датчика, чтобы база ехала с датчиком; позиция датчика задаёт точку остановки палеты; для смещения от текущей позиции — флаг «относительно». [palletizing-robot-programming]
- Палетизация: три вложенных цикла (Z снаружи, Y посередине, X внутри); инициализация и инкремент счётчиков должны быть в правильных вложениях; при сбросе смещений во вложенных циклах нужны отрицательные значения; `wait_pallet` вызывайте в начале цикла X. [palletizing-robot-programming]
- Ползунок интерполяции проверяет весь путь намного быстрее, чем запуск play; точки правьте touchup'ом; видимое обнаружение столкновений подсвечивает проблемы на панели и в 3D. [olp-basic-workflow-for-welding]
- Автоматические решатели работают только если активированы — проверьте, что кнопки решателя доступны. [olp-basic-workflow-for-welding]
- ⚠ OLP-панель наведения (4.8): ПКМ по кнопкам настраивает действия (Via, Auto Search, Multipath, удаление); путь резки строится по наружным рёбрам, а не поверхностям; для зигзага настраивайте Stroke Length/Width. [introduction-to-robotics-olp]
- ⚠ OLP-покраска: визуализация толщины краски и калибровка распыления по реальным данным краски; база данных путей переиспользует наборы параметров. [introduction-to-robotics-olp]
- ⚠ Сварка без приспособлений (4.9): sync-сообщения в программах манипулятора и сварочного робота должны точно совпадать; отпускание в манипуляторе — строго после sync-оператора сварки; направление подхода задавайте «Set Direction» с эталонной деталью, иначе деталь не вставится. [jigless-welding-programming]
- ⚠ KUKA OLP (4.5): без правильного submit логика ввода-вывода блокирует движение; в submits используйте выражения KRL вроде `not $In_100`; KRL чувствителен к регистру; позиции подхода задавайте вдали от деталей. [kuka-olp-101-learn-about-this-new-feature-in-visual-components-4-5]
- ⚠ KUKA OLP: машинные данные регенерируются только при значительных изменениях макета; E6POS в KRL можно менять для укладки без пересборки; .src/.dat экспортируются для реального робота. [kuka-olp-101-learn-about-this-new-feature-in-visual-components-4-5]
- KUKA.Sim: время движения RCS достоверно, время ожидания сигнала зависит от компьютера; масса и инерция инструмента прямо влияют на время цикла RCS; превышение грузоподъёмности вызывает ошибку момента удержания. [kuka-sim-addon-part-1-programming]
- KUKA.Sim: ось 6 (запястье) часто — узкое место по скорости, оптимизируйте ориентацией точки или относительным движением; сглаживание (C_Dis) на финальной точке сохраняет скорость вместо остановки. [kuka-sim-addon-part-1-programming]
- KUKA.Sim: бесконечный цикл с приращением смещения базы выводит робота за досягаемость и вызывает ошибку программного ограничения; для повреждённых машинных данных есть чекбокс «Генерирование данных робота» на вкладке RCS. [kuka-sim-addon-part-1-programming]
- KUKA.Sim: диаграмма трассировки позволяет перейти ко времени без повторной симуляции; экспорт в WorkVisual сохраняет синтаксис, базу/инструмент и сигналы. [kuka-sim-addon-part-1-programming]
- KUKA SafeOperation: без активированного BBRA робот может коснуться защитной зоны и продолжить движение; его раннее включение показывает реальное поведение остановки. [kuka-sim-addon-part-2-configure-kuka-safeoperation]
- KUKA, линейный модуль: не двигайте робота по дорожке в джоге при начальной настройке — используйте «Свойства компонента»; машинные данные обновляются только через них; изменение Rated travel требует фоновых расчётов (ждите). - ⚠ MELFA (5.0): RT Toolbox 3 — только для виртуального контроллера, Ethernet — только для реального робота. [melfa-robot-connectivity-plugin]

- «Reload simulation structure» обновляет списки переменных с обеих сторон; булев сигнал true включает путь конвейера без правки поведения. [make-a-simple-conveyor-plc-ready]

## Физика

- Объекты без Physics Entity не реагируют на гравитацию и коллайдеры контейнера и проваливаются сквозь него. [model-a-physics-container, model-a-physics-feeder]
- Коллайдер на block feature автоматически добавляет Physics Entity; Physics Entity задаётся на узел, соседние узлы не затрагиваются. [model-a-physics-feeder]
- Открытым полкам нужны боковые и нижние коллайдеры, иначе детали «проливаются»; для закрытых ящиков — коллайдеры на всех гранях; «Precise» collider обворачивает сложную геометрию (полки, поддоны). [model-a-physics-container]
- Kinematic — для питателей и конвейеров (предсказуемое движение), In Physics — для объектов под гравитацией; для связи physics и non-physics компонентов берите One-Way Path (статический контейнер), а не Physics Path. [model-a-physics-feeder]
- Физический питатель: если созданные компоненты исчезают после конца пути, они выпали из симуляции — держите питатель подключённым к конвейеру; рамки пути ориентируйте по X, Z вверх. [model-a-physics-feeder]
- Физический конвейер: если детали падают в начале пути, толкающий элемент (клин/блок) не покрывает область; коллайдер parent наследуется child-элементами; удаление collider у child при наличии у parent снижает точность. [model-a-physics-conveyor]
- Мягкие ограничения дистанционного шарнира требуют и spring constant, и damping; длина collider кабеля должна примерно совпадать с лимитом дистанции. [model-a-distance-joint]
- Для затухания: −1 отключает затухание при тестировании; solver iterations не заменяют сопротивление внешним силам — комбинируйте с затуханием; на spring-шарнирах сочетайте spring force, damping и limits. [linear-and-angular-damping]
- Очень высокая плотность на мелких объектах может обрушить конструкции — тестируйте постепенно. [material-density]
- ⚠ VR (4.2): захватываемым объектам нужны и «VR Pickable», и «Physics Entity»; чтобы объекты лежали на поверхностях, физический тип — «В Физике». [introduction-to-interactive-vr]

## Импорт CAD и экспорт

- Каждый импортированный CAD-файл создаёт свой компонент; для объединения геометрию нужно скопировать вручную, а «присоединение» не объединяет — компоненты остаются двумя. [import-and-combine-different-cad-files]
- После вставки геометрии выравнивайте её по началу компонента через Snap > Origin; пропавшую после удаления геометрию ищите по галочке Invisible в свойствах элемента. [import-and-combine-different-cad-files]
- Для робота из шаблона каталога: скопируйте геометрию из источника, вставьте в шаблон, удалите источник. [import-and-combine-different-cad-files]
- Планы этажей: используйте ортогональную проекцию (перспектива искажает позиционирование); «Привязка» берёт точку начала, «Выравнивание» — любую точку; поддерживаются до трёх точек для положения и поворота; привязывайтесь к краям/углам. [import-and-export-floorplans]
- Облако точек: только ASCII (.xyz, .pts); масштаб часто отличается в 1000 раз — исправляйте элементом «Преобразовать» с выражением масштаба, без переимпорта, и проверяйте «Измерением». [import-point-cloud]
- Python-импорт облака: умножайте координаты PTS на 1000 (метры → мм); делите цвет 0–255 на 255, иначе цвета выбелены; проверяйте порядок каналов (RGB/BGR). [import-point-cloud-with-python-api]
- Python-импорт облака: после добавления всех точек вызовите `point_set.update()` и `comp.rebuild()` — иначе не отрендерится; парсинг строк оборачивайте в `try-except`; большие облака сперва тестируйте на малой выборке. [import-point-cloud-with-python-api]

## Визуализация и запись

- Cylindrical-отображение текстуры превращает примитив в непараметрическую геометрию (радиус потом не поменять); перед применением подгоните размеры цилиндра под размер текстуры. [how-to-use-texture-mapping-tool]
- Если ось Z цилиндра совпадает с осью Z компонента, текстура растягивается на верхней/нижней гранях; Spherical равномерен только на настоящих сферах; Planar лучше всего для плоских и неправильных форм. [how-to-use-texture-mapping-tool]
- Перед текстурированием изолируйте нужную область «Slice» (например, логотип только спереди); для применения координат элементы должны быть схлопнуты (Collapse); U/V tiling — повтор по горизонтали/вертикали. [how-to-use-texture-mapping-tool]
- ⚠ Трансляция на YouTube (4.0.4): «Виртуальное время» даёт стабильную трансляцию независимо от CPU; F11 — режим «Презентация»; нужна верифицированная учётная запись YouTube; задержка 30+ секунд. [live-stream-a-simulation]
