# Лайфхаки R-Pro — часть 1

## Интерфейс и навигация

- Ctrl+F быстрее всего вписывает всё в вид, если вы «потерялись» в сцене. [basics-of-visual-components]
- Alt+Q включает режим фокуса на выбранном объекте, Shift+Alt+Q — вместе с иерархией родитель–потомок; для нескольких объектов сначала выделите их с Ctrl. [focus-on-your-layouts-using-focus-mode]
- В режиме фокуса нефокусные объекты не только полупрозрачны, но и невыбираемы: сдвиньте ползунок непрозрачности вправо, если нужно с ними работать. Режим сохраняется во время симуляции, параметры можно менять на лету. [focus-on-your-layouts-using-focus-mode]
- Экспортированное изображение содержит только 3D-геометрию, без панелей интерфейса. [basics-of-visual-components]
- Виртуальные компоненты (например, из питателей) существуют только во время симуляции — в планировке их не найти. [basics-of-visual-components]
- Ctrl+двойной клик автоматически соединяет совместимые части геометрии. [ecatalog-factory-facilities-an-overview]
- Выделение компонента в дереве построения подсвечивает его в планировке, двойной клик приближает камеру. [ecatalog-process-modeling-library-components-an-overview]
- Стрелки клавиатуры позволяют быстро подстраивать значения параметрических компонентов. [ecatalog-factory-facilities-an-overview]
- Размер подписи рамок настраивается в «Файл» → «Параметры» → «Экран»; крупные подписи сильно облегчают визуальную проверку положения рамок. [export-and-import-a-robot-program]
- Настройки резервного копирования лежат в «Файл» > «Настройки» > «Основные», а не в отдельном меню. [4-3-new-features-essentials-version]
- Расширения (Python add-ons) появляются только после перезапуска программы; ZIP перед копированием в «Мои команды» нужно распаковать. [find-and-use-python-add-ons]
- Большинство расширений после установки появляются на ленте во вкладке Program; искать их на форуме удобно через поле поиска во вкладке Help. [find-and-use-python-add-ons]
- Команды для автозагрузки при старте приложения вешайте на событие on_start в инициализационном файле; вкладки панели статистики — на on_app_initialized в `__init__.py`. [clear-and-save-output-messages, create-tabs-and-layouts-in-statistics-dashboard]
- Расширение в папке «Мои команды» (Visual Components Documents 4.0 > My Commands) с `__init__.py` — способ сохранить вкладки панели статистики между сеансами; вкладки, созданные из скрипта компонента, временны и исчезают при удалении компонента или очистке 3D-мира. [create-tabs-and-layouts-in-statistics-dashboard]
- Если пункт меню или кнопка не срабатывает, а в панели вывода «command not found», команда не связана с пунктом меню; ID команды должен совпадать с ID ссылки в пункте меню. [add-a-gallery-menu]
- Тип элемента для пункта меню галереи — «GalleryMenuToolItem», а не «GalleryMenuTool». order = -1 ставит элемент в конец группы или секции. [add-a-gallery-menu]
- SVG-иконки в меню можно указывать просто по имени файла из папки icons программы; цвет пользовательских SVG по умолчанию 393939 (чёрный в светлой теме, белый в тёмной). [add-a-gallery-menu]
- ⚠ F1 открывает онлайн-справку откуда угодно; онлайн-справка отличается от .NET API и Python 2.7 CHM-документации, а для работы офлайн офлайн-справку надо скачать с форума. (В R-Pro справка может быть локальной.) [access-help-files-and-online-material]

## Каталог, коллекции и источники

- Коллекция «Текущие открытые» показывает все используемые в макете компоненты без дубликатов — незаменима для больших планировок. [add-a-collection]
- Добавленные в коллекцию компоненты могут не показываться, если они помечены как устаревшие — включите «Показать устаревшие компоненты». [add-a-collection]
- Удаление коллекции или группы коллекций удаляет только закладки: компоненты остаются; вложенные элементы группы при её удалении разгруппируются. Если элементы не появились сразу — перезапустите программу. [add-a-collection, add-a-collection-group]
- В коллекцию можно перетащить несколько компонентов, выделив их с Ctrl; порядок в группе меняется перетаскиванием перед другим элементом. [add-a-collection, add-a-collection-group]
- Группы коллекций можно вкладывать друг в друга; удобно заводить группу на проект и класть в неё коллекции, смарт-коллекции и источники. [add-a-collection-group]
- Предсвязанные источники «Мои модели» и «Мои открытые модели» — самый простой способ подключить локальные папки (они уже связаны с «Документами»). Каталог обновляется сам при добавлении файлов. [add-a-local-folder-as-a-source, ecatalog-content]
- Автоматически найденные пустые папки в коллекциях не показываются, пока не добавлены вручную как источник. [add-a-local-folder-as-a-source]
- Снятие «Видимый» скрывает источник из коллекций, но он остаётся в поиске и в смарт-коллекции «Все модели». [add-a-local-folder-as-a-source]
- Смарт-коллекции берут метаданные из свойств компонентов и обновляются сами; редактируются двойным кликом; фильтр «and» требует выполнения всех условий — для «любого из» берите «or». [add-a-smart-collection]
- Папки процессных компонентов в eCatalog имеют префикс «PM»; «По производителю» — лишь другое представление тех же компонентов. [ecatalog-content]

## Моделирование компонентов

- Поведения привязаны к рамкам, а не к геометрии: именно рамки задают положение поведений. [common-behaviors-in-component-modeling]
- Тип сустава нельзя менять, пока компонент подключён — сначала отсоедините. [common-behaviors-in-component-modeling]
- Если стол не вращается, проверьте, что назначен сервоконтроллер и настроены операции. [common-behaviors-in-component-modeling]
- Для компонента с подвижными частями сначала разделите CAD-геометрию на отдельные звенья (например, «Извлечь звено» для дверей), и только потом применяйте Machine Wizard или создавайте сервоконтроллеры. [create-machines-using-machine-wizard, creating-a-custom-machine]
- После Machine Wizard всегда вручную проверяйте и правьте положение и направление рамок: ось X определяет направление подхода робота, и ошибка даёт неправильную ориентацию или падение деталей. [create-machines-using-machine-wizard, creating-a-custom-machine]
- Строить машину нужно пошагово, проверяя каждый компонент до добавления операторов процесса; двери проверяйте инструментом «Взаимодействие» до запуска процессной симуляции. [creating-a-custom-machine, create-machines-using-machine-wizard]
- Время обработки лучше задавать именованным свойством-распределением, а не жёстко заданной задержкой. [creating-a-custom-machine]
- Неправильные пределы сервоконтроллера блокируют движение суставов. [creating-a-custom-machine]
- Корректная установка родителя: синяя стрелка от потомка к родителю показывает прикрепление; система координат «Родительская» задаёт положение относительно начала родителя. [attach-components-in-3d-world]
- «Моделирование» > «Сохранить компонент как» сохраняет родителя со всеми потомками; при проблемах с перезаписью существующего файла используйте «сохранить как». [attach-components-in-3d-world]
- Команда «Открепить» доступна только у компонентов, прикреплённых к другим компонентам, но не к миру. Автоприкрепление при клонировании может прицепить копии не туда — перетащите для переприкрепления. [attach-components-in-3d-world]
- Замена робота не корректирует позиции под новую геометрию — столкновения обычны. Чтобы робот не «уезжал», зафиксируйте положения «К миру», потом переставьте вручную; совместимые роботы подсвечиваются жёлтым. [exchange-robots]
- Для интерактивного изменения длины конвейера используйте инструмент «Взаимодействие», не редактируя свойства. [conveyors-and-inline-machines-an-overview]
- Совместимые интерфейсы конвейеров соединяются автоматически при выравнивании (зелёная стрелка); на конвейер можно навесить процессоры (датчики, моторы, упоры). [conveyors-and-inline-machines-an-overview]
- Fence Builder параметрический: после использования его можно удалить, забор останется; секции забора затем редактируются независимо. [ecatalog-factory-facilities-an-overview]
- Физическое подключение внешних осей (PnP) происходит автоматически при совместимых интерфейсах «один к одному»; чекбокс «Интерфейсы» (Главное > Показать) показывает и позволяет удалять удалённые соединения (значок ножниц на проводе). [connect-external-axes-to-a-robot]
- Значения внешних суставов (E1, E2, E3) автоматически появляются в операторе движения после подключения осей; имена E1–E3 не настраиваются, назначение зависит от порядка подключения. Touch-up — простейший способ записать их точно. [connect-external-axes-to-a-robot]
- После перемещения робота на рельс и обратно значения суставов могут не вернуться сами — сбросьте симуляцию. [connect-external-axes-to-a-robot]
- Декаль лежит поверх материала, не меняя геометрию; небольшое смещение (порядка 10 мм) убирает мерцание Z-fighting; перевёрнутую текстуру поверните на 180° вокруг Z; Blend держите на максимуме. [adding-a-decal]
- Roughness: меньше — глянец, больше — матовость; bump map создаёт иллюзию рельефа без изменения геометрии. [adding-a-decal]
- Выпуклая оболочка содержит заметно меньше треугольников, чем исходная геометрия (пример из урока: 1272→436) — выгодно для производительности. [4-3-new-features-professional-and-premium-versions]
- Режимы импорта CAD-сборок различаются: «feature» берёт дерево элементов, «node» — дерево узлов, «component» создаёт новый компонент. [4-3-new-features-professional-and-premium-versions]
- Режим углового паттерна годится для круговой раскладки клонов; инструмент паттерна работает только с выбранным компонентом. [4-3-new-features-essentials-version]
- Свойства-ссылки на узел можно выбирать инструментом-пипеткой прямо в 3D; список ссылок может содержать узлы разных компонентов. [create-a-reference-node-property]
- Все компоненты имеют свойства «Спецификация», «Наименование в спецификации» и «Описание в спецификации». [create-drawings]

## Свойства и скрипты (Python)

- delay() работает только в OnRun; в OnSignal он ничего не делает или подвешивает скрипт. Для логики по времени переносите код в OnRun и используйте condition. [blocking-functions-in-python-api-2-7-part-1]
- condition() требует функцию, возвращающую boolean; после проверки обязательно вытаскивайте очередь или сбрасывайте сигнал, иначе условие остаётся True и скрипт зависает. [blocking-functions-in-python-api-2-7-part-1, blocking-functions-in-python-api-2-7-part-2]
- trigger_condition избавляет от ручного сброса сигналов; в OnSignal при нескольких сигналах фильтруйте нужный через if. [blocking-functions-in-python-api-2-7-part-2, blocking-functions-in-python-api-2-7-part-1]
- Прямое присваивание signal.value = False не вызывает OnSignal в других скриптах; для рассылки изменения как события используйте метод signal(). [blocking-functions-in-python-api-2-7-part-2]
- Опция trace execution и print помогают найти, где скрипт завис, и посмотреть дескрипторы сигналов и содержимое очереди. [blocking-functions-in-python-api-2-7-part-1]
- comp.parent_component даёт доступ к свойствам родителя (например, конвейера, для синхронизации скорости). Точечная нотация comp.property_name удобна, а get_property() нужен, если в имени свойства пробелы или оно не атрибут. [blocking-functions-in-python-api-2-7-part-2]
- Servo joints доступны списком с индексацией с нуля. [blocking-functions-in-python-api-2-7-part-2]
- Значения свойств хранятся в канонических (SI) единицах: `prop.value` температуры даёт Кельвины, а присвоение 38.0 — это 38 К, а не 38 °C. При установке значений из пользовательского ввода конвертируйте через `unit.convert_to_canonical()`. [define-quantities-and-units]
- Кнопка («Button») — свойство без значения (None), служит для вызова действий; обязательно задайте обработчик on_changed, иначе кнопка ничего не делает, и используйте константу VC_BUTTON, а не строку «button». [create-a-button-property, clear-and-save-output-messages]
- Перед созданием свойства проверяйте, существует ли оно, чтобы не плодить дубликаты; свойства можно создавать и на элементах, а не только на компонентах. [create-a-button-property, display-id-of-part-in-process]
- set_selection() менеджера выделения принимает список, даже для одного объекта; app.find_command() находит .NET-команды интерфейса, например fill_selected. [create-a-button-property]
- Не все типы свойств поддерживают ограничения: шаг — только вещественное, целое и строка; диапазон — только вещественное и целое. Значения шага должны точно совпадать с записями step_values. [create-properties-with-constraints]
- Для целочисленных свойств допустима шестнадцатеричная запись (0x0000FF = 255). [create-properties-with-constraints]
- Свойства с ограничениями, созданные скриптом, требуют ограничения при создании; позже их можно править через GUI. [add-and-edit-robot-variables]
- Сгруппированные свойства задаются в виде «ГруппаИмя::ИмяСвойства» (два двоеточия); векторное свойство — через Vector(x, y, z); Ctrl+Space даёт автодополнение. [add-and-edit-robot-variables]
- Список ссылок на узлы при создании через API требует явного синтаксиса `"list[ref(node)]"`. [create-a-reference-node-property]
- У распределений 64 потока планировки по умолчанию дают одинаковые начальные значения — меняйте их отдельно для разных последовательностей; чтение значений вне on_run() даёт новые значения при каждом обращении, а воспроизводимость работает только во время симуляции. [create-a-distribution-property]
- Псевдослучайные последовательности воспроизводимы при использовании потоков — удобно обмениваться планировками в команде. Индекс потока вне 0–63 даёт разные значения при каждом запуске. [create-a-distribution-property]
- Фрагменты кода вставляются по Ctrl+J; изменённый фрагмент подхватывается только после закрытия и повторного открытия скрипта; имя файла `.py` — это имя фрагмента. [create-and-edit-snippets]
- Точные имена констант API (например, VC_one_way_path) копируйте из Help > Python API > Constants. [create-and-edit-snippets, create-properties-with-constraints]
- Для записи вывода в файл открывайте его в режиме 'a' и пользуйтесь оператором with; путь берите из папки «Общие документы», чтобы не упереться в права доступа; пути с пробелами заключайте в кавычки как строки. [clear-and-save-output-messages]
- Пример кода для vcViewAnimation в справке Python API — готовая заготовка для анимации камеры, но имена видов в нём нужно заменить на свои, иначе анимация не будет ссылаться на ваши виды. [animate-camera-movements]
- Сохраните нужные виды в View Editor до написания анимации камеры; Transition delay 0 даёт мгновенный переход; задержки измеряются во времени симуляции, а не реальном. [animate-camera-movements]
- Фрагменты CSV читать/писать экономят время при обработке данных в скриптах компонентов. [4-3-new-features-professional-and-premium-versions]
- Чтобы дисплей не показывал старый ID после сброса симуляции, очищайте свойство при старте и при уходе детали; делайте его «только для чтения»; проверяйте наличие свойства перед чтением. ⚠ Урок помечен как check — механика отображения может отличаться в R-Pro. [display-id-of-part-in-process]
- Операции робота используют свойства компонента как глобальные переменные; переменные операции локальны и недоступны в вызванных подоперациях. [add-and-edit-robot-variables]
- Контроллер: `get_robot()` без аргументов внутри скрипта робота автоопределяет контекст. [control-a-picker-robot-2]
- `robot.pick_moving_part()` требует движущегося конвейера, для неподвижной детали — `pick()`; при движении конвейера вводите `translate_x` в place(). [control-a-picker-robot-2]
- Отфильтровать уже взятые детали можно лямбдой `lambda x: x not in picked`; перед захватом проверяйте, что ссылка на деталь не потеряна. [control-a-picker-robot-2]

## Расширение на C# (плагины)

- Имя сборки фонового плагина должно начинаться с «UX.» или «plugin.», иначе он не обнаруживается; Platform target — x64. [add-a-background-plugin]
- IoC.Get<T>() избавляет от шаблонного кода MEF Import; для Lazy<T> нужен .Value, внедрение через конструктор — нет. [add-a-background-plugin]
- После изменения значений свойств вызывайте Rebuild(), чтобы обновилась геометрия; при типизированном свойстве приводите результат создания к IProperty<double>. [add-a-background-plugin]
- Для отладки плагина в реальном приложении подключайте внешний отладчик к engine.exe; FillWorld() масштабирует вид по всем объектам сцены. [add-a-background-plugin]

## Process Modeling: потоки, ресурсы, операторы

- Транспортные связи создавайте кликом по узлу (метке/узлу, а не подписи); панель «Шаги процесса» должна совпадать с визуальными связями в 3D. [adding-transport-links, create-a-simple-robotic-cell]
- «Очистить неиспользуемые» убирает лишние связи, не затрагивая остальные; «Автосвязь» ускоряет создание при большом числе подключений. [adding-transport-links, 4-3-new-features-essentials-version]
- Пустая иконка исполнителя в шагах означает, что ресурс не назначен; случайный слив без соответствующего шага создаёт осиротевшие связи. [adding-transport-links]
- Если деталь застряла на питателе — нет шагов процесса: создайте их в редакторе процессов. [create-a-simple-robotic-cell]
- Транспорт по умолчанию «интерполирующий» (детали летят между узлами); для физического перемещения смените на робота. [create-a-simple-robotic-cell]
- Если источник и место назначения не совпадают, детали не движутся и ждут освобождения предыдущего процесса; «Транспортный узел» тоже должен совпадать. [destination-and-source]
- Контейнер в качестве источника и назначения создаёт буферную очередь на конвейерах; время процесса станка влияет на буферы после него. [destination-and-source]
- «Транспортный узел» обязан быть соединён с «Контейнером», иначе поток процесса не работает. [common-behaviors-in-component-modeling]
- Контейнер привязан к узлу — перемещение узла физически перемещает контейнер; он иерархичен, а Path-контейнер двигает детали вдоль рамок от начала к концу. [container-concept-in-visual-components]
- Контроллер/блок вместимости позволяет нескольким контейнерам делить общую вместимость и предотвращает deadlock; он должен быть соединён с путями, иначе поток не пойдёт. [common-behaviors-in-component-modeling, container-concept-in-visual-components, creating-an-inline-process]
- Transition Signal (Boolean): true — прибытие, false — убытие; полезно для логики процесса. [container-concept-in-visual-components]
- Для Path-датчиков установите trigger и reset на Trailing Edge, чтобы фиксировать полный выход детали. [common-behaviors-in-component-modeling]
- В Встроенном процессе операторы должны идти в порядке Transport In → Delay → Transport Out; не забывайте «Out Interface» или «Path Out», иначе детали застревают. [creating-an-inline-process]
- Неверное положение рамок во встроенном процессе приводит к «прыганью» или исчезновению деталей; флажок «Типы рамок» помогает их видеть. [creating-an-inline-process]
- Правило вместимости (по умолчанию) выбирает первый порт со свободным местом, но не учитывает источник входа — если он важен, берите фиксированное правило. [define-routing-rules-and-routes]
- Для слияния потоков в один конвейер и углов подходит правило одиночного явного порта; фиксированное правило сопоставляет входные порты выходным. [define-routing-rules-and-routes]
- Циклическое правило требует минимум двух подключений, при одном работает как явный порт. [define-routing-rules-and-routes]
- В правилах по таблице свойств и по типу продукта задавайте порт по умолчанию для продуктов без совпадения. [define-routing-rules-and-routes]
- Правила можно комбинировать в дереве маршрутов (одно для порта 1, другое для порта 2). [define-routing-rules-and-routes]
- Включите «показать названия портов»: правила зависят от точных имён портов; смена числа или положения портов может разорвать подключения интерфейсов — переподключите вручную. Ориентация портов (вход/выход) должна быть верной. [define-routing-rules-and-routes]
- Контроллеры транспорта нужно сочетать с ресурсами: робот с контроллером робота, человек — с контроллером человека; компоненты навигации задают пути мобильных роботов. [ecatalog-process-modeling-library-components-an-overview]
- «Стандартные связи» на контроллере задают параметры всех связей сразу; пользовательские параметры связи их переопределяют — деактивируйте пользовательские, чтобы вернуть стандартные. [approach-and-resource-position]
- В операторе открепления (detach) при выгрузке поддона: «открепление множества» удаляет все экземпляры типа; пустой поддон надо транспортировать явно, иначе он остаётся в процессе. [depalletizing-using-pm-detach-statement]
- Если поддон и детали появляются одновременно, добавьте задержку; для тестирования уменьшайте количество в паттерне. [depalletizing-using-pm-detach-statement]
- Имена переменных локальны процессу, их можно переиспользовать в разных операторах транспорта. [depalletizing-using-pm-detach-statement]
- Датчик области автоматически открывает дверь при обнаружении человека; людей пропускает сквозь стены, если дверь не автоматическая — свяжите её с сигналом. [add-safety-equipment-in-robotic-cells]
- Исключите из детектирования препятствия (станцию, проезд, робота) и сам сканер, иначе пути не будут работать. [add-safety-equipment-in-robotic-cells]
- В типах сборочных изделий Auto Assembly быстрее ручного создания и сам определяет прикреплённые детали; порядок индексов определяет последовательность добавления. [creating-assembly-product-types]
- Новые слоты наследуют тип детали только если выбран предыдущий слот; фильтр продукта ограничивает типы деталей в слоте. [creating-assembly-product-types]
- Для сеток слотов — «Блочный паттерн», для рядов — «Линейный»; при копировании слотов проверяйте высоту по Z. [creating-assembly-product-types]
- Закрытие редактора без сохранения может потерять структуру сборки. [creating-assembly-product-types]
- Старые свойства продукта не удаляются автоматически — пересмотрите их перед добавлением новых; «Все шаблонные свойства» быстро добавляет стандартный набор. [editing-product]

## Статистика и панели

- Статистика робота (простой, занятый и т.п.) считается только при использовании операторов установки состояния; оператор ставьте в начале блока, где состояние активно, иначе статистика искажается. [elseif-and-set-state-statements-in-robot-programming]
- 100% простоя в статистике — проверьте, что операторы Set State есть, а программа зациклена (включите зацикливание в свойствах исполнителя). [elseif-and-set-state-statements-in-robot-programming]
- Добавляйте задержки внутри условных блоков, чтобы состояние отражало реальное время работы; интервал панели статистики независим от скорости симуляции. [elseif-and-set-state-statements-in-robot-programming]
- В компонентах статистики: калькулятор не получит события, если выходной сигнал не соединён; диаграмма берёт названия из пользовательских свойств. [ecatalog-statistics-components-an-overview]
- Для времени между сигналами сначала запишите программу, затем оберните её операторами выхода; отслеживать можно по ID или пользовательскому свойству. [ecatalog-statistics-components-an-overview]
- Заглушки (stubs) панели статистики не могут перекрываться: если A1 занимает строки 0–4, следующая начинается со строки 5. [create-tabs-and-layouts-in-statistics-dashboard]
- Статистика с моделью состояний (idle/busy) нужна для метрик загрузки машины. [common-behaviors-in-component-modeling]
- Перед созданием своих диаграмм посмотрите готовые шаблоны диаграмм статистики. [4-3-new-features-essentials-version]

## Роботы и программирование (OLP)

- Программа должна начинаться с PTP-движения — отсутствие начального PTP источник многих проблем; линейные движения наследуют конфигурацию предыдущего PTP и могут не достичь цели при неверной конфигурации. [basics-of-robotics]
- PTP быстрее линейного на больших расстояниях, так как суставы движутся независимо. [basics-of-robotics]
- Для точной записи значений суставов после смены конфигурации используйте touch-up, а не ручной ввод углов. [basics-of-robotics, exchange-robots]
- Удаляйте лишние полные обороты (например, −361° замените на −1°): они тратят время и ресурс; неверная конфигурация может раскрутить первый сустав и задеть окружение. [basics-of-robotics]
- Привяжите базовые рамки к движущимся компонентам (родительский узел), чтобы позиции двигались вместе с ними; смещения базовой рамки удобны для паттернов без дублирования кода. [basics-of-robotics]
- Шестерёнка на панели джога показывает модификацию рамки в реальном времени. [basics-of-robotics]
- Операторы: if/elseif/else выполняют только первый совпавший блок; elseif лучше вложенных if. Оператор ожидания после блока синхронизирует цикл. [elseif-and-set-state-statements-in-robot-programming]
- Выбирайте TCP до создания операторов движения; при вырезании операторов в подпрограмму вырезайте, а не копируйте, и не забудьте добавить вызовы подпрограмм в главную последовательность. [creating-subprograms-and-calling-robot-routines]
- Копии операторов сохраняют старые имена (P1, P2, P3) — переименуйте сразу. [creating-subprograms-and-calling-robot-routines]
- Инструмент выравнивания привязывает позиции к углам геометрии цели. [creating-subprograms-and-calling-robot-routines]
- Переменные операции инициализируйте в начале через Assign Variable; суставы сбрасываются при сбросе симуляции — для сохранения используйте «Сохранить текущее состояние», которое сохраняет состояние ВСЕХ компонентов мира. Сгруппированные свойства при сбросе сохраняются — сбрасывайте явно в подоперации. [add-and-edit-robot-variables]
- Перед экспортом программы робота сохраните компоновку; программы лучше экспортировать в XML рано, а проверенную — сохранять как шаблон. [export-and-import-a-robot-program]
- Переключение оператора (новое в 4.6) позволяет временно отключить оператор без удаления. [export-and-import-a-robot-program]
- При переносе программы на нового робота: Snap в режиме «origin» выравнивает позицию, а рамку инструмента нового робота нужно перевыравнивать вручную; проверьте соответствие соединения A5 (или аналога). [export-and-import-a-robot-program]
- После импорта используйте «play» или «Сохранить состояние», а не просто reset, иначе изменения рамки инструмента могут не сохраниться. [export-and-import-a-robot-program]
- Подход и положение: смещение подхвата X, Y, Z смещает позицию ресурса относительно точки. [approach-and-resource-position]
- «Stop on collision» годится для поиска проблемных мест, но не как окончательное решение; мелкие столкновения (инструмент с деталью) могут повторяться. [exchange-robots]
- Экспорт программы перед заменой робота и импорт в нового — запасной вариант, если замена вызывает слишком много проблем. [exchange-robots]
- Для комбинации «синхронные движения с вращающейся деталью» нужна аккуратная настройка родительского узла базовой рамки. [basics-of-robotics]

## Обнаружение столкновений и геометрия столкновений

- «Выделение против мира» быстро находит пересечения выбранного со всем миром; подкомпоненты (схват) попадают в проверку только если включены в детектор. [detect-collisions]
- Режим «первое» быстрее для диагностики, «все» показывает полную картину; минимальное расстояние подсвечивается в 3D с точным значением. [detect-collisions]
- Допуск >0 работает как раннее предупреждение (например, 100 мм — срабатывает при расстоянии меньше 100); остановка при столкновении с допуском >0 остановит перед касанием. [detect-collisions]
- Сохранённый детектор независим от общего переключателя и неактивен, пока не отмечен. Пользовательские детекторы проверяют несколько частей сразу (схват + крепление против конвейера); узлы детектора можно разворачивать для выборочного отключения суставов. [detect-collisions]
- ⚠ Геометрия столкновений: выпуклые оболочки тоньше блоков и позволяют роботу подойти ближе; без нажатия «Create» работа теряется; для сложных деталей используйте ручное создание. Урок записан в версии 5.0 — интерфейс может отличаться в R-Pro. [create-collision-geometry]
- ⚠ Проволоку сварочной горелки не включайте в коллайдер — она должна контактировать; для сопла нужен отступ; режим точности повышает точность, но замедляет решатель — только для критичных компонентов. (Версия 5.0.) [create-collision-geometry]

## Подключения (ПЛК, роботы, OPC UA)

- Для внешнего контроллера отключайте «executor» (Is enabled) робота в свойствах компонента, иначе программа выполнится дважды. Это общее для ABB, Epson, Denso, FANUC. [abb-robots-connectivity-plugin, connect-an-epson-virtual-robot-controller-using-opc-ua, denso-robot-connectivity-plugin, fanuc-connectivity-plugin]
- После включения функции подключения перезапустите приложение, иначе вкладка не появится; после правок в PLC выполните «Перезагрузить структуру сервера» (ПКМ), чтобы увидеть новые переменные. [connect-a-local-twincat-plc, abb-robots-connectivity-plugin, connect-to-winmod-simulation]
- Если панель подключения пуста, ПКМ → Reload simulation structure (или Reload server structure для WinMOD). [abb-robots-connectivity-plugin, connect-to-winmod-simulation]
- Группы переменных можно включать и отключать во время работы; режим обновления при работе менять нельзя. Cyclic — регулярный опрос, event-based — по событиям 3D. [connect-a-local-twincat-plc, connect-a-remote-opc-ua-server]
- Выход Timer.Q очень короткий: после таймера сбрасывайте part_at_sensor в false, иначе следующий процесс не запустится. [connect-a-local-twincat-plc]
- Код PLC можно править без отключения от симуляции. [connect-a-local-twincat-plc]
- Для OPC UA на Codesys добавьте конфигурацию символов в проект, иначе переменные не видны; порт и IP должны совпадать на обеих сторонах (стандартный порт 4840). [connect-a-remote-opc-ua-server]
- Переменные VC отображаются как component_name.signal_name; для быстрого поиска пользуйтесь полем фильтра. [connect-a-remote-opc-ua-server]
- PLCSIM Advanced: включите виртуальный Ethernet-адаптер, согласуйте IP и маску с TIA Portal, включите OPC UA в свойствах PLC (может потребоваться обновление прошивки), создайте сертификат и включите «Support simulation during block compilation». [connect-plcsim-advanced-using-opc-ua]
- Виртуальную пуско-наладку возможно вести в Professional/Premium; Essentials — только для обучения. [connect-plcsim-advanced-using-opc-ua]
- WinMOD: блок связи в Element Library > Active Elements > Controller > Communication elements; вкладка Transmit — исходящие сигналы, Receive — входящие; тип operand (analog/binary) должен совпадать с типом сигнала; Ctrl+Space открывает список operands; коммуникация должна быть включена в свойствах проекта WinMOD. [connect-to-winmod-simulation]
- Для сопоставления свойств вида Path Behaviors > Speed в WinMOD должен быть отмечен флажок «Behavior properties». [connect-to-winmod-simulation]
- WinMOD и SIMIT — только в Premium; Visual Components может служить визуализатором 3D для WinMOD/SIMIT. [4-3-new-features-professional-and-premium-versions]
- ABB: устанавливайте RobotStudio и post-processor заранее; виртуальный контроллер должен быть полностью online; ошибки I/O statement означают, что сигналы не определены в контроллере — загрузите EIO.cfg через Load parameters. Postprocess генерирует модуль RAPID и EIO.cfg — храните вместе. [abb-robots-connectivity-plugin]
- ABB: Warm start применяет конфигурацию без полной перезагрузки; сигналы лучше проанализировать заранее в Signal editor. [abb-robots-connectivity-plugin]
- ⚠ Epson (версия 5.x): обязательно создайте сертификат OPC UA в RC+; при фильтре «value» (заглавная) видны только VALUE-атрибуты суставов; actual_position лежит в parameter set каждого сустава. [connect-an-epson-virtual-robot-controller-using-opc-ua, epson-robot-connectivity-plugin]
- ⚠ Epson: в RC+ можно использовать scan controllers вместо выбора пути проекта; панель connected variables позволяет мониторить и форсировать значения. [epson-robot-connectivity-plugin]
- ⚠ Denso: слушатель b-CAP должен быть свёрнут, но запущен — закрытие рвёт связь с RC8; после переключения контроллера в режим симуляции выключите и включите соединение RC8. [denso-robot-connectivity-plugin]
- ⚠ Denso: для сопоставления фильтруйте по «signal maps» (сигналы) и «Degrees of freedom objects» (атрибуты VALUE суставов). [denso-robot-connectivity-plugin]
- FANUC: Ctrl+click выбирает несколько свойств VALUE; сопоставление входных портов — в направлении симуляция→сервер; teach pendant Roboguide показывает выполнение подпрограммы в реальном времени. [fanuc-connectivity-plugin]
- Doosan: операторы input/wait input signal не поддерживаются — как обходной путь используйте порты выхода; без включённого I/O-симулятора в Dart Studio выходные сигналы не срабатывают; TCP задаются вручную, базовые рамки приходят из пост-процессора. [doosan-robot-connectivity-plugin]
- VAL 3 (Staubli): переключение режимов симуляции требует сброса, а не паузы; в режиме Virtual робот не синхронизируется с контроллером до нажатия Play; Jogging обучает позиции без запуска симуляции, а Start synchro синхронизирует робота с контроллером. [create-and-simulate-a-val-3-application]
- ⚠ Fronius: загруженное на источник задание нельзя ни удалить из VC, ни изменить — только клонировать; создать задание с нуля нельзя, отбрасывайте задания локально до загрузки. (Версия 5.0.) [fronius-connector]

## Импорт CAD, чертежи и экспорт

- STEP экспортирует тесселированную геометрию (старые САПР могут её не прочитать); JT загружается быстрее STEP, но без текстур; OBJ сохраняет текстуры; VRML — без материалов. [export-to-step-jt-and-more]
- ⚠ Drawing Block Reader (DWG) — отдельное расширение с форума, нужна версия 4.4 и выше. [dwg-block-reader]
- Чертежи не сохраняются отдельно от файла планировки; масштаб задавайте на шаблоне чертежа или на каждом чертеже (ретроактивно не применяется); «Масштабировать до заполнения» подгоняет чертёж под страницу. [create-drawings]

## Визуализация и запись

- Минимальный шаблон 3D PDF только с полем «3D window» полностью работоспособен; шаблоном может служить даже слайд PowerPoint, экспортированный в PDF; имена и типы полей должны совпадать точно, иначе поля не заполнятся. Проверяйте шаблон сразу, записав короткую симуляцию. [create-a-3d-pdf-template]
