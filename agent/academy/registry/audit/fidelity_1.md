# Аудит достоверности и полезности, выборка K=1

Истина: транскрипт (часть 1). Часть 2 (английский конспект) использована только чтобы найти, на каком этапе вошла ошибка. Метки [Digest] означают, что ошибка уже есть в английском конспекте, [Lesson] означает, что она появилась на этапе русского урока.

**Wrong**
- Шаг 12 «выбирайте «release» на станцию повторного захвата» пропускает следующую кнопку «align to regrab station» (6:33). В уроке её нет вообще, хотя это основное действие шага. [Digest]
- Шаг 14 «для создания конфигураций размещения»: в транскрипте конфигурации появляются после повторного нажатия «add alignment points» и выбираются из списка. Две дополнительные стороны дают четыре конфигурации. Этой механики в уроке нет. [Digest]

**Missed** (самое ценное)
1. Нет шага «создать подпрограмму на каждую деталь (part A)» (3:56). Шаг 19 вызывает «part A», хотя нигде не сказано, что её надо создать и что вызов добавляется в main program оператором call (11:05).
2. Нет «добавьте вызов release part на шаге Process» ни для станции повторного захвата, ни для финального отпускания (7:29, 10:12). Без него магнит не отпускает деталь. В уроке вызван только grab part.

Затем иконка «select from 3D world» и клик по сборке. Список элементов отсортирован по похожести имени, выбранный элемент подсвечивается в 3D. Потом скрыть сборку и нажать create. Также пропущено, что робота можно подвинуть по рельсу, если он «barely reaching» (8:24).

**Terminology**

- «панели наведения» (hover panel) и «панели инструментов операторов» (statements toolbar) звучат кальками. Названия в R-Pro нужно взять из ресурсов.
- «Disassemble and Create»: в транскрипте две отдельные кнопки («click disassemble and create»). Составное имя выглядит угаданным.

**Danger for the assistant**
- Урок для 4.9.0, инструмент Assembly Operations мог появиться позже версии, на которой собран R-Pro. Пометка «скорее всего работает» ничем не подтверждена. Ассистент не должен обещать, что инструмент есть в R-Pro, не проверив.
- Больше ничего опасного.

**Scores**: fidelity 4, usefulness 3 (скелет верный, но самые «неочевидные» шаги вызова и выбора элемента потеряны).

**Verdict**: fix. Добавить создание подпрограммы part A и вызов её в main; добавить call release part; расписать выбор элемента через assembly helper; добавить «align to regrab station»; убрать выдуманную «ловушку»; привести названия UI к одному виду.

## register-a-command

**Unsupported**
- Шаг 4 «caliber.micro, create3D.shared, ux.shared»: на слух «caliber micro», «create 3D shared», «ux dot shared». Это реконструкция. В шаге 6 та же библиотека уже названа Caliburn.Micro, то есть внутри одного урока два написания.
- Шаг 6 «using Visual Components.Create3D; Visual Components.UX.Shared»: имена с пробелом не компилируются. По моим знаниям API правильно VisualComponents.Create3D и VisualComponents.UX.Shared; транскрипт говорит только «visual components create 3D», «visual components dot ux dot shared».
- Шаг 8 `base("hello_command")`: в транскрипте «hello command» («suffix of command»). Подчёркивание придумано. Дальше везде используется то же угаданное написание.
- Шаг 5 «Нажмите Assemblies»: в транскрипте такой вкладки нет, сказано лишь «assembly from the .NET framework».
- Ловушка «а не net_command»: вариант `net_command` в транскрипте не упоминается.
- Python-имена `GetApplication()`, `FindCommand`, `GetComponent()`, `GetProperty`, `command.Execute`, `button.on_changed`: на слух «get application», «find command», «execute», «on changed equals my function». Регистр восстановлен догадкой. В Python-API Visual Components методы обычно в lowerCamelCase (getApplication, findCommand, getProperty), а событие свойства называется OnChanged. В R-Pro (Python 2.7) вызов с заглавной буквы даст NameError/AttributeError. [Digest, в разделе «Скрипты» есть оговорка «не проверено», но шаги подают написание как факт]
- Имя команды `"netCommand"` под вопросом: докладчик говорит «lowercase n followed by camel case upper C», и в реальном API, по моим сведениям, команда называется dotNetCommand. Первая буква «d» могла потеряться при распознавании. Требует проверки в R-Pro. Это центральный вызов всего Python-блока.

**Wrong**
- Шаг 17 «Удалите/закомментируйте тела методов Exit и Initialize» противоречит шагу 18 («В Initialize создайте ICommandRegistry…»). В транскрипте удаляется только заготовка Exit («when it exits we don't need to worry about that»); в Initialize вызов как раз пишется (5:31–6:30). [Digest]
- Шаг 9 «Используйте лампочку для реализации ActionItem, получите метод Execute()»: в транскрипте метод Execute добавляется как `public override ... execute`, лампочка применяется позже для IPlugin (2:45 и 5:31). [Digest]
- Порядок: шаг 13 (переименование в MyHelloAction) стоит до создания MyPlugin, а в видео переименование делается после написания плагина (6:30). Безвредно.

**Missed**
1. Для Python-части нужен доступ к вкладке Modeling; без неё «you're going to have to write your own python command» (9:11). Для R-Pro это актуально.
2. Обработчик кнопки срабатывает при каждом изменении значения свойства («every time its value changes», 11:47), поэтому один клик может вызвать его не один раз; в уроке этого нет.
3. В конструкторе ActionItem можно задать ещё text ID и имя иконки, не только ID (1:53). Мелочь, но показывает, откуда берутся подписи в интерфейсе.

**Terminology**
- «caliber.micro» вместо Caliburn.Micro (см. выше); «IApplication», «IMessageService», «ICommandRegistry» разумны, но нигде не подтверждены.
- Названия вкладок оставлены английскими (Modeling, Home, Behaviors, Properties). Русский интерфейс R-Pro использует локализацию.

**Danger for the assistant**
- Python-фрагменты в шагах 29–43 дословно воспроизведут PascalCase-вызовы. В R-Pro (Python 2.7) это сломает скрипт, а novice не поймёт почему. Также неверное имя команды (netCommand против dotNetCommand) даст молчаливый провал `FindCommand`.
- Синтаксис `print button.Name` корректен для Python 2.7, здесь всё в порядке.
- Урок про C# и Visual Studio (.NET 4.5, x64, Output path в Program Files). Для novice-вопроса «как вызвать команду» ассистент не должен предлагать собирать плагин.

**Scores**: fidelity 3, usefulness 3 (мост «Python вызывает .NET-команду» нетривиален и полезен, но в нынешнем виде код с большой вероятностью не работает).

**Verdict**: fix. Заменить написание API на проверенное по R-Pro (getApplication/findCommand/getProperty/OnChanged, имя команды); убрать «Initialize»-противоречие в шаге 17; исправить Caliburn.Micro и пространства имён; пометить `hello_command` как условное имя; убрать «net_command».

**Verdict**: fix. Удалить выдуманную ловушку и «1.0»; заменить путь меню на Ctrl+N; исправить «AC outdoor unit»; сверить названия редактора и терминологию; в «Задаче» прямо указать, что здесь только навигация и обзор, создание сборки в уроке не рассматривается.

## palletize-using-pm-transportpatternin-statement

**Unsupported**
- Шаг 1 «Создайте три типа деталей: поддон, пластина, цилиндр». В видео они уже есть в стартовом макете («let me go to starting point, right now I have three products ... three product types»; файл sample-layout-start.zip), а название «plate» докладчик лишь выбирает для листа («I'm going to call this plate»). Создавать их не нужно, и про скачивание стартового макета в уроке ничего нет. [Digest]
- Ключевое слово «детектор» (detection volume) в списке слов взято из конспекта, в транскрипте нет. [Digest]

**Wrong**
- Шаг 10: X −427, Z +194, количество 5×3. Пропущено Y −215: докладчик читает из родительской системы координат «427 ... in x and −215 in y and 194 in z» (10:56). Без Y цилиндры встанут со сдвигом. Также «427 - 427» в транскрипте искажено речью, знак X надо проверить; этот знак в конспекте тоже взят на веру. [Digest/Lesson]
- Совет «Для замены сборочной палетизации переключитесь с Интерполирующего Контроллера на Робота или Человека». В видео другое: если нужно, чтобы паллетизировал робот или человек, надо добавить их в макет и выбрать соответствующий контроллер вместо interpolating transport (13:41). С «заменой сборочной палетизации» это не связано. [Digest]
- Совет «Если появится ошибка о потере состояния детали, переименуйте переменную и добавьте присоединение». Ошибка «product state within its flow sequence is lost» появилась у Transport Out; лечится так, чтобы Transport Out отправлял ту же переменную поддона, которая пришла в Transport In (в видео переменная названа pallet) (11:53). Присоединение (attach) добавляется позже по другой причине: детали не прикрепляются сами. [Digest]

**Missed** (самое ценное)
1. В фидерах нужно выбрать, что каждый производит: один plate, другой cylinders. Иначе «nothing is coming in» (7:09). В уроке этого нет. Нет и самого Transport In для поддона и настройки stop on origin (5:07), которые нужны, чтобы остальные операторы работали; не сказано, что в Transport Pattern In принимается только один тип продукта (plate или cylinders).
2. Шаг паттерна для цилиндров 200 по X и Y: высота цилиндра 200, радиус 100, значит шаг равен диаметру (9:01). В уроке про шаг только «Установите ... шаг паттерна» и «важен при количестве > 1». Само значение и логика потеряны. Также количество 2×2 по умолчанию надо менять на 1×1 для пластины.
3. Способ получить смещение: прикрепить цилиндр к поддону и прочитать значения в родительской системе координат (9:55–10:56). В шаге 9 это есть, но без Y и без указания, что в оператор вводится именно это смещение (в Z плюс 194 для следующих цилиндров) и что количество задаётся отдельно для +X (5) и +Y (3).

**Terminology**
- «Транспортировка Паттерна В», «Транспорт Из», «оператор присоединения», «Прикрепите»: Transport Pattern In / Transport Out / Attach переведены по-разному и непоследовательно; «дитя» (child) нужно заменить на «дочерний» или «потомок».
- «компоненты подачи» для feeder, «узел ПРОЦЕСС» для process node: сверить по ресурсам. Название «Каталог» ок.

**Danger for the assistant**
- Пропуск Y-смещения и значения шага даст неверную укладку. Фраза «создайте три типа деталей» уведёт novice от скачанного стартового макета. Опасного кода нет.

**Scores**: fidelity 3, usefulness 3 (приём «прикрепить, прочитать смещение в родительской СК» нетривиален и полезен, но запись неполная).

**Verdict**: fix. Добавить Transport In и stop on origin; указать выбор продукта в фидерах; дописать Y −215 и шаг 200 (диаметр); исправить совет про контроллеры и ошибку «state is lost»; убрать «детектор»; описать, что стартовый макет берётся из файла урока; унифицировать термины Transport Pattern In / Attach / Transport Out.

## robot-reachability-part-i

**Unsupported**
- «Parent координаты относительны к началу робота, делая сингулярности более ясными». О сингулярностях в транскрипте речи нет. Parent просто означает систему координат, привязанную к локальному началу робота (5:28). [Digest]
- «Из Home > eCatalog > Robot Pedestal» с готовым именем «Robot Pedestal»: в видео «a simple robot pedestal», название угадано. [Digest]
- «учитывайте смещение инструмента отдельно»: в видео только факт, что профиль относится к концу пятой оси, а не к TCP; рекомендации нет.

**Wrong**
- Шаг 9: измерение «→ -200 мм на Y» подаётся как проверка выравнивания. На самом деле измеряется ширина по Y (400), делится пополам (200) и деталь сдвигается инструментом Move на −200 по Y (2:39). Действие по центрированию и логика «пополам» потеряны. [Digest]
- Шаг 6 «Отключайте материалы при импорте» подаётся как обязательное. Причина в видео: «since we wish to apply our own material type» (1:48), то есть это выбор для данного примера.

**Missed** (самое ценное)
1. Проверка заданных точек (13:51): три point-to-point операторов, затем frame types > robot positions; недостижимая точка p3 становится жёлтой, при запуске суставы подсвечиваются, а в панели вывода появляется сообщение об ошибке (при включённом message panel output). В уроке этого нет вообще, хотя это лучший способ проверить досягаемость запрограммированных точек.
2. Раздел Limits (12:51): stop at limits, color highlight и message panel output; можно отключить stop at limits, чтобы робот выходил за пределы с подсветкой сустава. Также: при суставе 5 больше 30° точка вне досягаемости, TCP-snap за пределами не разрешён (10:09). В уроке есть только Color Highlight.
3. Размещение робота (4:30) и работа через интерфейсы: позиционер появляется в центре мира, робота ставят на одну линию (Y = 0 по зелёному значку Y в свойствах); после соединения интерфейсов (component = робот, interface = позиционер; можно протянуть связь мышью, затем выключить отображение интерфейсов) в панели Jog управляют наклоном стола (45°) и поворотом (90°, EJ2). В шаге 10 только «для соединения робота и позиционера», шага «Y = 0» нет, а ведь урок об установке робота.

**Terminology**
- «педестал» вместо «подставка»/«пьедестал»; «досягаемость» (ок), «сварочный факел» (обычно «сварочная горелка»).
- Все названия UI на английском (Jog, Hierarchy, Connect, Interfaces, Coordinates, Limits, Workspace, Envelope), хотя R-Pro русифицирован. В заголовках встречается «dropdown».
- «С выбранным робота» опечатка. «Plug and Play» и «PnP» чередуются.

**Danger for the assistant**
- Ничего вредного. Единственный риск: ассистент, не зная про Y = 0 и про Stop at limits, даст неполную рекомендацию по размещению робота.

**Scores**: fidelity 4, usefulness 3 (верный маршрут, но самые полезные приёмы проверки потеряны).

**Verdict**: fix. Убрать «сингулярности»; добавить Y = 0 для робота и условия соединения интерфейсов; добавить проверку по точкам (жёлтая p3) и параметры Limits; исправить шаг 9 (Move на −200 по Y после Measure); исправить опечатку и перевод «педестал».
