## Суть урока
Два этапа: (1) описать **сборку** во вкладке **«Детали»** (из шагов), (2) выполнить сборку **в процессе** на ручной рабочей станции операторами GetAssembly и Construct. Пример — **роутер** из 5 компонентов.

## Планировка (область «Главная»)
- Ручная рабочая станция (где собираем) + вторая станция (куда уходит готовая сборка; на практике — любой следующий этап), **человек**, **ТК человека** (подключить человека), **«Процесс подачи» — 5 штук**, по одному на каждый компонент (платформа, плата, крышка, WAN-порт, антенна — компоненты в планировке с уже настроенными осями, чтобы не было коллизий). Разнести компоненты, чтобы визуально было понятно.

## Вкладка «Детали»
1. Редактор типа деталей: удалить имеющееся, **добавить новую группу процессов**, в ней **5 типов деталей** (платформа, плата, крышка, WAN-порт, антенна) → каждому дать ссылку на компонент в планировке (указать).
2. В каждом **процессе подачи** выбрать свой **тип детали** (Product Creator).
3. **Сборка:** добавить новую группу процессов → в ней **«Добавить сборку»**. Создаётся **с одним шагом**, открыть **редактор сборок**: в нём **жёлтый куб** — заглушка шага. **Каждый шаг сборки создаётся с жёлтым кубом — его нужно редактировать:** левой кнопкой по нему → в окне выбрать **нужную деталь**, которая будет появляться на этом шаге. Шаг 1 — платформа; добавить ещё 4 шага (2 — плата, 3 — крышка, 4 — WAN-порт, 5 — антенна), имена шагам. Сборка = последовательность шагов. Закрыть редактор (или переключиться на планировку) — сборка готова и доступна в процессах.

## Процесс на станции
1. Транспортные связи: от процессов подачи → первая станция (где сборка) → вторая станция; исполнитель — **ТК человека**.
2. **Операции** → операция первой рабочей станции: убрать лишнее, оставить **TransportIn и TransportOut**, добавить ещё **4 TransportIn** (5 входящих компонентов): в каждом задать **переменную** (общая переменная для сборки — **parts**) и **тип детали** (по порядку: платформа, плата, крышка, WAN-порт, антенна).
3. Выражение **GetAssembly («Получить сборку»)**: тип — сборочное изделие → выбрать сборку 1; даёт свойства сборки, заданной во вкладке «Детали» (видны все компоненты по шагам).
4. Выражение **Construct («Создать сборку»)**: ссылается на сборку этого шага и **следует её порядку**; указать **переменную со всеми компонентами (parts)** — все 5 станут частями новой сборки.
5. **TransportOut** — отправляется **готовая сборка** (результат Construct), а не отдельные части.
6. Человек забирает готовую сборку и относит на следующий этап.

## Визуальная настройка (чтобы детали не «тонули» в столе)
В области «Моделирование» выбрать ручную рабочую станцию → у процесса добавить ещё один **Location** (напр. «Location 3») и поднять его; в Процессе → Операции для каждого компонента выбрать рамку положения **Location 3**. Для готовой сборки на второй станции — аналогично.

## Практическое задание «Сборка роутера» (PDF урока 11)
1. Добавить в планировку компоненты для сборки роутера.
2. Во вкладке «Детали» определить нужные **типы продуктов**.
3. Добавить новую группу процессов, добавить **сборку**, **5 шагов сборки**.
4. Каталог: **Человек, Процесс подачи (5 шт.), ТК человека, Ручная рабочая станция (2 шт.)** → в зону моделирования и разместить.
5. Процесс и транспортная связь, исполнитель — ТК человека.
6. Для каждого из 5 процессов подачи определить деталь.
7. Создать процесс для сборки роутера в процессе ручной рабочей станции (GetAssembly → Construct).
8. Результат: файл планировки **«Урок_11»** со сборкой роутера из 5 компонентов.

## Лайфхаки и ловушки
- Забытый «жёлтый куб» в шаге = пустой шаг: каждый шаг сборки нужно «назначить» деталью.
- Одна и та же переменная (parts) в Construct и в 5 TransportIn — иначе сборка не соберётся.
- В TransportOut — именно переменная готовой сборки.
- Детали «тонут» в столе → добавить и поднять Location.


## Как это делает агент (проверено в R-Pro 2.2.2)
Сборка роутера. Тип-сборка: `part_type(...)` для 5 деталей + `define_assembly(имя, группа, шаги, типы)` (шаги: платформа — корень, остальные — гнёзда с `pos` и `order`).
ВАЖНО (R-Pro 2.2.2): схема «5 × TransportIn → GetAssembly → Construct» из видео зацикливает перенос в нулевое время (`CannotTransportAlreadyAtTarget`, часы стоят, окно EXCEPTION_ACCESS_VIOLATION) — НЕ использовать. Рабочая схема: склад платформы — `CreateProduct` с `AssemblySteps=[шаг платформы]` + `TransportOut`; склады остальных деталей — `CreateProduct` + `TransportOut`; пост (компонент с кадрами `ResourceLocation` и `Center`, например «Inline Process»; у «Manual Workstation v2» кадра Center нет) — `TransportIn Mode=0` (платформа, `ProductVariableName="Engine"`) → `GetAssembly` (`AssemblyDataSource=1`, `AssemblySteps=[...шаги 2–5]`, `ReturnVariableName="Order"`) → `TransportIn Mode=1` (`AssemblyVariableName="Engine"`, `AssemblyOrderVariableName="Order"`) → `Work` (человек, `Controller=beh(тк,"TC")`) → `TransportOut`. Детали носят люди «ТК человека»; два маршрута: сборка (платформа → пост → следующий этап) и детали (склады → пост). Присваивание `TransportOut.DestinationNode` вешает мост. Порядок свойств оператора важен: `AssemblySteps` после `ProductType`/`Assembly`.
