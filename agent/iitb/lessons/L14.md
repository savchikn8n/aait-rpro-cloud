## Суть урока
Выражение **WaitSignal («Ждать сигнал»)** на примере дверей станка. Исходный станок — модель в формате **STEP** без поведения и свойств (всё настраиваем с нуля).

## Подготовка компонента (область «Моделирование»)
1. Выделить части левой двери → **«Извлечь звено» (Link_1)**; то же для правой (**Link_2**).
2. **Link_1:** в окне **JointType** — **поступательное**, ось **+X**, **пределы 0 … 550** (мм).
3. **Link_2:** **«поступательный ведомый элемент»**, ось **−X**, в свойствах соединения → **«Драйвер»** указать **первое звено** (оно ведёт второе).
4. Добавить набор **поведений**: **«Исполнитель процесса»** (Process Executor — здесь пишется логика операции), **Сервоконтроллер** (управляет звеньями; выбрать, каким соединением управляет — **J1**), **BooleanSignal** с именем, напр. **DoorSignal**.

## Процесс (область «Процесс» → «Операции»)
1. Выбрать **процесс в станке** (его Executor) → кнопка **«+»**, чтобы добавить **новый процесс** (изначально пустой).
2. Добавить выражение **WaitSignal**: **компонент** — станок, **сигнал** — DoorSignal, **условие `True`**. Затем выражение **MoveJoint**: **контроллер** — ServoController, **соединение** — J1, **целевое значение 550** (мм — на сколько сдвинется дверь), **время движения 2 с**. (В видео: сначала двери закрыты, когда поступает продукт; после технологической операции их открывают, чтобы забрать деталь — логика порядка зависит от задачи.)
3. Второй WaitSignal: тот же компонент и сигнал, **условие `False`**; **MoveJoint** — J1, целевое значение **0**, время **2 с**.
- **Ловушка:** если в MoveJoint не выбран контроллер/соединение — двери не поедут. Быстро исправляется в свойствах выражения.

## Проверка сигналов
Запустить симуляцию: компонент ожидает, когда сигнал станет **true**. Чтобы вручную менять значение сигнала: область «Главная» → **инструмент «Сигналы»** → щёлкнуть по значку значения сигнала компонента (убрать лишние панели) → true — двери закрываются, false — открываются.
Для реального процесса сигнал нужно **отправлять из других компонентов или из самого станка** (выражение **«Отправить сигнал»** в нужной операции): после технологической операции деталь выходит и в этот момент на DoorSignal отправляется нужное значение — двери открываются/закрываются.

## Практическое задание «Ожидание сигнала» (PDF урока 14)
Подготовка компонента (два звена, JointType, оси ±X, сервоконтроллер, пределы 0…550, исполнитель процесса, DoorSignal) → создание процесса (WaitSignal + MoveJoint для закрытия и открытия) → проверка: симуляция, двери открываются и закрываются по значку значения сигнала.

## Лайфхаки и ловушки
- Ведомое звено без «Драйвера» не двигается — укажи первое звено.
- Пределы 0…550 — иначе MoveJoint вылезет за допустимое.
- Нет сигнала-источника — компонент вечно «ожидает».


## Как это делает агент (проверено в R-Pro 2.2.2)
Двери станка по сигналу. Станок строят на каталожном «Узле процесса» (`Flow Node Process.rpro`): процесс компонента, созданного с нуля, не попадает в менеджер процессов и не запускается. Звенья: `d1 = comp.createNode(VC_NODE, "Link_1")`, `d1.JointType = VC_JOINTTYPE_TRANSLATIONAL`, `d1.Dof.AxisType = VC_JOINTAXIS_PLUS_X`, `d1.Dof.Name = "J1"`, пределы `"0"`/`"550"`, `d1.Dof.Controller = servo`; второе звено — `VC_JOINTTYPE_TRANSLATIONAL_FOLLOWER`, ось `MINUS_X`, `d2.Dof.Driver = d1.Dof`. Сигнал `sig = comp.createBehaviour(VC_BOOLEANSIGNAL, "DoorSignal")`.
Процесс (`r = clear_routine(comp)`): `TransportIn Mode=0` → `WaitSignal` (`Component=comp, Signal=sig, WaitTrigger=True`) → `MoveJoint` (`Controller=servo`, потом ОТДЕЛЬНО `Joint = servo.getJoint(0)`, `TargetValue=550`, `MotionTime=2`) → `WaitSignal(False)` → `MoveJoint(0)` → `TransportOut`. Станок ставят в поток «подача → станок → отгрузка» (`link(..., "InterpolatingTransport", группа)`).
ЛОВУШКИ: `Joint` присваивают ПОСЛЕ `Controller` (смена контроллера его сбрасывает); в `Joint` нельзя класть `Dof` — это вешает мост; значение сигнала шлют методом `сигнал.signal(True)` — присвоение `.Value` процесс не будит (в справке: «Setting this value does not trigger the OnSignal event unless you use the signal() method»); значение сигнала сбрасывается в исходное состояние при reset.
