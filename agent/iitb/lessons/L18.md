## Суть урока
Подготовка к чемпионату по компетенции «Бережливое производство». Область **«Lean Six Sigma»** — инструменты: **SIPOC**, **Yamazumi**, **VSM**, **Диаграмма спагетти**. Планировка загружается заранее (на ней проводят анализ). **Оговорка:** такой вкладки может не быть в более ранних версиях (в R-Pro 2.2.2 на этом стенде окна VSM/Yamazumi не найдены — их строят по данным прогона); в версиях с областью Lean Six Sigma — инструменты ниже.

## SIPOC
Вкладка **Lean Six Sigma → SIPOC**, справа панель инструмента. Заполнить **5 элементов**: **Поставщик (Supplier), Вход (Input), Процессы (минимум 3), Выход (Output), Потребитель (Customer)**. Поставщика и вход можно выбрать **одним узлом процесса**. Рабочие места — **кнопкой «Добавить шаг»** (если нужно анализировать больше трёх операций; в примере 4). Выход/потребитель — по аналогии со входом. **Время** анализа симуляции (в примере 600 с) → «Построить диаграмму»: симуляция проигрывается до заданного времени и останавливается. Таблица: **1-я строка — полезное время процессов, 2-я — количество выпущенной продукции** по каждому элементу; есть интерактивные поля для **комментариев**. Экспорт таблицы в **PDF**.

## Yamazumi
Инструмент Yamazumi → выбрать этап; **шаги добавляются как в SIPOC**, **порядок выбора = порядок в производственном процессе**. Заполнить рабочие станции, поля: **отдел, тип процесса, метод измерения, дата снятия статистики**. Напротив операции указан **тип работы** (добавляет ценность / не добавляет / потери); можно **изменить тип** (если операция выполняет другую функцию — считай потерей) → «Обновить»: суммарные значения пересчитаются. Для каждой операции и каждого шага внутри — время выполнения и тип; внизу — **суммарное время** и по каждому типу работы; данные доступны и в виде **графиков**; экспорт в **PDF**.

## VSM (карта потока создания ценности)
Визуализирует весь путь продукта от поставщика до потребителя, показывая каждый этап и выявляя потери; позволяет увидеть процесс целиком и **рассчитать Process Time (время цикла)**.
- Перед построением указать **смену оснастки и брак**, если они есть, через **комментарии с кодами** (для смены оснастки — комментарий, содержащий **«SO»**; на примере таких операций нет). Без них будут ошибки «на планировке отсутствует корректное построение смены оснастки / брака», но **построению диаграммы они не мешают**.
- Ввести **плановое производственное время** (пример 20 мин) и **потребность в продукции** (пример 11 шт. за это время) → построить. Результат: **время такта (Takt)**, полное время производства, время выполнения процесса, по каждой станции — **время цикла**, брак, смена инструмента (в примере нули); группы процессов и **гистограмма постов**: **столбцы выше линии такта — узкие места**.
- Экспорт в **PDF**, поля «технолог/оператор проекта», рабочий центр линии, статус (первоначально/обновлённая). Диаграмму можно строить не по всем группам процессов, а по **выбранной**.

## Диаграмма спагетти
Показывает **транспортировки линиями на планировке** (по каким путям перемещались компоненты) и **гистограмму пройденных путей**, обновляется в реальном времени, можно остановить через время (напр. 11 мин). Пример: human 3 прошёл 86 м, другой оператор почти не двигался, ещё ~8 м, **мобильный робот — 160 м**. Применение: **минимизировать перемещения операторов**, сделать маршруты прямыми и короткими, снять нагрузку с операторов.

## Лайфхаки и ловушки
- Для VSM заранее размечай смену оснастки и брак комментариями — иначе ошибки в панели (но расчёт идёт).
- Столбец выше линии такта = узкое место → кандидат на оптимизацию (см. также `rpro_lean_optimize` у агента).
- Порядок шагов в Yamazumi/SIPOC должен совпадать с реальным порядком операций.
- Тип работы можно править вручную и обновлять — быстрый «что если».
